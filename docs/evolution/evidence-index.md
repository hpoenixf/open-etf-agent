## v0.2: explicit extensions with shared evidence ownership

- Skill discovery advertises metadata, while actual body/resource reads carry hashes; reading a method does not prove a model followed it.
- Official SDK v2 accepted polluted stdout, and the failing negative test itself leaked an unexpectedly successful session until the outer timeout. Preserve both defects rather than calling a timeout a passing cleanup test.
- Maintained SDK v1 was selected for exact 2025-11-25 behavior, with a larger 95-package dependency graph and installation scripts disabled. It is not a claim to implement the newest protocol.
- A self-consistent source hash was insufficient: the acquired document/page also must match the request. Remote input schema must agree with the narrow local binding, not only have matching property names.
- Actual stdio cancellation and timeout leave the owned child absent. Complete fixture SSE is separately tested; no live model capability is inferred.
- [Observed failures and fixes](../verification/v02-observations.md), [dependency decision](../dependencies/sdk-selection.md), [artifact provenance](../verification/v02-evidence-provenance.json).

## v0.3: local cooperation and honest effect identity

- Synchronous root reservations prevent two read workers spending the last tool unit; fixed read workers are not model agents.
- Before Hook inputs are copied/frozen, permitted patches are revalidated, and a trusted alias never creates tool permission. Configuring an alias alone does not perform it: the first demo correctly rejected its missing explicit callback.
- An alias to save_report exposed a real observability defect: the file existed but the original name suppressed file_saved. Dispatch and effects now use effective identity, with original preserved.
- A release callback before final log processing could announce an earlier status. It now observes Runtime finalization attempts, not a fictional guarantee that every external resource closed.
- One-level fixture-child reuses Runtime with only allowed read_page documents and shared budget. Live independent model behavior remains unproved.
- [Actual failures and regressions](../verification/v03-observations.md), [artifact hash provenance](../verification/v03-evidence-provenance.json).

## v0.4: immutable originals are not per-call observations

- Before RED, independent review corrected a faulty test idea: switching document A to B was not proof of same-document version retention. The actual test now reopens both versions of one document.
- One ResultStore replaces Host's source Map. Immutable originals, typed numeric derivations and an ordinary content index permit exact reread without pretending to resume execution.
- A source-owner integration initially replaced repeat MCP observations with the first stored acquisition. The actual negative reproduced the identity mismatch; stable source identity and current call observation are now separate.
- Context's initial sourceId/hash shortcut could launder a lookalike tool payload into an original ref. Actual RED led to explicit Host refs, text-hash checking and complete intrinsic identity verification.
- Query variation is connected to actual ordinary read_page calls, not merely a ranking helper. Zero hits expose the missing report rather than fabricate a comparison.

## v0.5: questions fixed before implementation

The initial fourteen assertions now have actual RED→GREEN evidence, followed by integration and independent review negatives. The offline candidate passed 124 tests and seven independent demos; live semantics remain unproved.

- Forgetting a stored entry is weaker than removing its old typed text from the next model input: search results, historical write arguments and derived-note dependencies can each reintroduce it. Historical execution records and already exported reports remain historical facts.
- A Memory write's intent must be operator-bound and scoped, not a Boolean supplied by the model. A one-use grant requires durable reservation before mutation; failures after reservation can consume authority without completing the operation. That is an explicit partial effect, not permission for silent replay.
- Compaction must save bytes against the actual reference-only view, not an inflated raw-text baseline. Note metadata and original refs count toward the comparison.
- Generating a summary and persisting a note are both asynchronous. The original basis or Memory revision may change in either interval; an immutable note file alone is not evidence that the note was adopted.
- [Proposed contracts and verification order](../../openspec/changes/v05-notes-memory/design.md). [Actual terminal execution evidence](../verification/v05-observations.md) preserves Hook-copy forgetting, lost partial Memory effects, note scope and observe-event failures instead of retelling them as first-try success.
