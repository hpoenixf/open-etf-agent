# Project 上下文字节预算

新建 Project 默认在配置中持久保存 `contextBytes: 1048576`。顶层 `contextBytes` 可显式设为 1 至 1,048,576 的整数。这是应用序列化上下文的**字节**限制，不是模型 token 窗口，也不保证所有请求都能装入。

旧配置、旧任务缺少该字段时，保持原语义：普通任务 32,000 字节，Knowledge 任务 1,048,576 字节。读取旧记录不会补字段或改变哈希。通过原生 `updateResearchProject` 的配置哈希 CAS 修订，可以为后续新任务显式设置新值；已准入任务仍使用各自冻结配置。修订时省略 `contextBytes` 表示保留“缺字段”的历史解释；只改其他配置时应保留当前字段。

Runtime 仍保留原问题和最新完整工具组，只允许把符合条件的旧来源正文替换为不可变引用，不静默截断必要内容。仍装不下时，在下一次模型派发前明确失败。报告已经保存，不会把失败任务自动算作完成。

Gateway 另有 1,048,576 字节的**完整编码请求**上限。工具定义、来源元数据、JSON 转义和协议外层都占空间，因此 1 MiB 上下文并不等于可放入 1 MiB 原文。序列化开销仍可能提前触发拒绝，不自动重试、不启用超额付费，也不改变模型窗口。

Compaction 是单独显式启用的能力。原默认 `compaction.thresholdBytes: 16000` 保持不变；扩大上下文不会暗中提高该阈值或开启摘要。如需调整，应显式配置。模型生成摘要仍会消耗任务及共享额度中的请求预约；扩大上下文本身不授予额外次数或费用权限。
