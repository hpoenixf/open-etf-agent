# Run control and termination ownership

This v0.20 implementation concentrates **Runtime decisions**, not authority, in `src/run-control.mjs`. The existing Session `claim.finish` remains the fenced durable terminal writer. Session cancellation, RootBudget reservations, grants, Child identity, and Gateway/Admission uncertainty remain with their original owners. The decision helper cannot execute effects, create authority, return budget, settle tickets, or reopen a terminal Run.

## Facts and decisions

- A successful tool result continues the original paired transcript. A local refusal permits one correction only when the original Host can reproduce an exact, JSON-stable, identity-bound pure validation proof, in a single-call group without hooks, partial effects or unknown effects. The correction uses the same Run and existing model budget. A second refusal stops with `CORRECTION_LIMIT`.
- Existing calculation validation proofs remain supported. New report proofs cover argument shape, bounded nonempty text, source-ID collection shape and attachment collection shape. **They do not prove that a source exists, that a numbered citation is valid, that a file is readable, or that permission exists.** Stateful errors without the original Result proof described in the bounded reference-correction section below remain fail-closed; the pure shape proof alone never authorizes that correction. A source ID that happens to resemble a ResultRef is still accepted when the original Result owner actually acquired it; spelling does not define ownership.
- A sealed model final may finalize only with the original required report and no unsettled outcome. This is not a new output-only model phase and does not manufacture a report from final text.
- After Publication commits, an ordinary `onPublication` notification exception cannot undo the exact committed body. After the sealed final is committed and no further model/tool dispatch is possible, notification gets a separate 100 ms observation window; an unsettled asynchronous callback is unconfirmed, not proof of remote stop. This window requires a responsive Node event loop: a trusted callback that synchronously blocks that loop cannot be preempted by a timer. Callbacks are not a sandbox for arbitrary code; process isolation is not provided or claimed. Runtime rechecks actual abort, original fence and receipt before recording `PUBLICATION_NOTIFICATION_UNCONFIRMED`. Notification delivery is not asserted. Cancellation, identity corruption and lost ownership still stop the Run.
- Cleanup/readback observations cannot overwrite an existing cancellation or primary failure. Required result integrity still prevents success. Release-observer and final-log failures are explicitly unconfirmed observations, not permission to erase a committed result. The legacy `run_finished` log event is marked `pre-settlement`; the actual Session terminal record is authoritative, not that earlier observation.
- Non-Error throws and throwing `code` accessors are safely classified without losing an already-reserved unknown operation. A bounded string code (1–200 characters, no control characters) is retained as a diagnostic; other values become `EXECUTION_FAILED`. An external `CANCELLED` string is not proof of user cancellation: Runtime checks its original abort signal or the original Session state.

## Persistence and compatibility

`controlObservations` is an optional bounded additive checkpoint field with exact owner/code pairs and the actual Run ID. Legacy checkpoints without it remain valid. The final outcome must match the checkpoint observations. Old terminal failures are returned as their old terminal facts; upgrading does not retry them. A new report validation envelope is checked by the current Host and must not be silently interpreted by an older implementation.

The original deadline contract is unchanged: no new work after the deadline, while a legitimate already-known terminal result can still be settled by the original fenced Session writer. Cancellation remains observable during asynchronous release. Host stop is interruption, not user cancellation. Unknown model/tool effects and their Admission occupancy are never released merely because cleanup succeeded or a process disappeared.

## Deliberate remaining boundaries

This change does not remove Child's sole-call restriction, introduce arbitrary plugin retry, infer generic plugin calculation citations, or retry unknown requests. Stateful report-reference correction needs an exact historical Result-owner contract, not a guess from the final source collection. Publication notification callbacks are distinct from `onClaim` and `onCheckpoint` control/test hooks; those are not blanket-swallowed. A `publication-committed` control checkpoint allows explicit process-stop testing independently of notification. The public durable integration uses the original Session contract, including its pure checkpoint preflight; an incompatible store is rejected before creating a Run or dispatching a model.

The original v0.20 forty-scenario observations remain tied to their executed source versions, including failures and the unknown C07 summary. New implementation, offline regression checks, separate paid repairs, and final release qualification are different claims.

## Bounded correction of acquired-result references and mixed Child groups

A registered ResultRef is not an original source ID. When the original Result owner can prove a typed reference was used instead of an acquired source, or a numbered citation exceeds the acquired calculation/source sequence, it may offer one correction. Exact source identity wins even if its string resembles a ResultRef. Unknown arbitrary IDs, permission failures, corrupt records, and uncertain effects do not receive this permission.

The proof retains the complete bounded, ordered Result index at the original sealed proposal. The existing Session writer anchors that basis, Run, grant, call and unchanged Host in the first result-committed transaction. Recovery verifies that historical basis and the original records; later acquisitions do not rewrite the earlier decision. The private basis is omitted from model working messages, including custom Gateway calls. This uses the existing trusted local Session storage model, not protection against arbitrary rewriting of its database. Hooks, protection profiles, partial effects and unknown effects remain outside this correction path.

A mixed group containing an original serial Child is refused before any member executes. The Child owner validates its original binding; the existing Session transaction writes every ordered not-dispatched result together, preserving exact call pairing. The Runtime may spend its one correction opportunity to request a separate invocation. There is no tool or Child budget debit for the rejected group; the model request already consumed its original budget. Repeated mistakes stop at the existing correction limit. Unknown tools, special response control, already-started historical groups, cancellation, deadline, fence and budget restrictions remain enforced. A refusal is not successful work, and the Child still has no independent publication authority.

## Summary observation windows

New research projects and explicit configuration revisions persist a 60-second summary observation window unless one is supplied. The supported maximum is 120 seconds. Existing project/task records retain their stored value; historical projects without a stored summary setting continue to use their former 10-second application default. The low-level compaction API retains its historical default for compatibility. Older readers that only supported 30 seconds reject a new longer definition rather than silently changing it.

The window does not extend the original Run deadline, increase model/summary attempt limits, or bypass cancellation and provider HTTP limits. A timed-out dispatched summary remains unknown and occupied; aborting the local wait does not prove remote cancellation or justify a replay. The 60-second default is a practical bounded configuration, not a claim of a universal provider latency guarantee.
