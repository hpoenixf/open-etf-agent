# Publication-first answers

Publication owns the fact that an answer was delivered. Report artifacts and citation quality are separate facts. `readResearchReport` remains strict and requires an original Report receipt. `readResearchOutput`, the research CLI report commands, and the local Reader read committed Publication content; they never turn a failed historical proposal into a delivery.

For an ordinary, nonprotected Root Run, the original Host can produce a `report-citation-assessment@1` after checking the original Result basis, acquired source bytes, document scope, original PDFs, and attachments. Exact source IDs keep their citation positions; unknown IDs and unsupported numbered markers are explicitly unverified. A document ID is never guessed into a source ID. Validated source identity or a registered calculation does not semantically validate financial claims.

The original Runtime consumes this settled singleton result at its existing `result-consumed` checkpoint. It asks the original Session/Publication owner to publish the verbatim candidate body with its bound assessment, without another model call or save attempt. Session checks the original Run, active claim, paired call/result, request hash, scope, acquired basis, and absence of unsettled effects. A cold restart repeats the same owner checks and reuses the original idempotent Publication commit. The rejected `save_report` remains rejected and has no fabricated Report receipt; the Run can complete its explicitly degraded answer delivery.

Ordinary sealed-final answers likewise remain delivered when no optional Report was produced. Protected output, authorization, revocation, cancellation, deadline, fence, hash and pairing checks retain their original owners. Generic tool failures do not acquire blanket continuation permission from this change.

Diagnostic log failures are observations, not execution or publication authority. Cleanup and result-readback observations cannot revoke an already committed answer. Original integrity checks still apply where an operation consumes evidence or resumes execution. Historical failed Runs are never reopened or relabeled successful.

The Reader displays escaped literal text and the committed citation audit with a financial-verification warning. Audit output lists at most 512 distinct numbered markers, with an explicit complete/partial flag and the total number of unverified markers; the full original answer is never truncated. Source verification describes the publication-time assessment, not an ongoing claim about mutable external content. The Reader does not execute model HTML or links. Report artifacts remain independently readable through their original owner; an unavailable Report does not hide an independently committed answer.

## Child capacity is local admission information

A serial Child owner's exhausted `maxChildren` allowance now returns an explicitly non-admitted `childAdmission` result, bound to the original request and settled Child slots. It acquires no source and runs no Child/provider request. Main may continue using already acquired evidence within the unchanged root budget. Same-call duplication, foreign scope, active or unknown Child effects, parent cancellation, deadline and stale fences remain hard boundaries. Recovery without a matching Child only reconciles this exact, positively established capacity observation; it does not allocate a replacement Child.

Previously, test 22.3 documented that a failed Child consumed its slot and a subsequent capacity rejection terminated Main with `CHILD_EXECUTION_LIMIT`. The slot-consumption fact remains unchanged. The new test distinguishes local capacity exhaustion from authority to terminate Main; historical terminal Runs are not changed.

## Optional Memory is local read information

The original selected Memory library distinguishes a missing or forgotten optional entry from failed storage or permission checks. `memory_read` returns a `memory-unavailable` observation with no preference text when the original owner proves absence or verifies its immutable tombstone. This successful lookup does not claim that an entry was read, and it does not end Main. Strict library reads and write authorization are unchanged. Corrupt bytes, changed library identity, invalid arguments and unapproved writes still fail.

Original read results are bound to the requested ID and selected library during recovery. A historical entry may be verified against its immutable record after forgetting, but its text remains removed from future model inputs. An already redacted `unavailable-memory-projection` is not an accepted tool result and remains outside optional history compaction. This preserves the small projected group instead of treating a projection as original evidence.
