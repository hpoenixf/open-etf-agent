# Context fitting (v0.34 candidate)

This is the A14 public subset, not a release or full private-module parity claim.
Use existing `research project init/update --config` and task submission. Add this
optional field to the existing project JSON alongside the independent hard limit:

```json
{
  "contextBytes": 1048576,
  "contextWorkingSetBytes": 65536
}
```

This fragment is not a complete project configuration. `contextWorkingSetBytes`
is an integer from 1 to 1048576 and defaults to absent (legacy behavior). It is
frozen into each admitted task. Updating a project affects new tasks, not old
ones. Existing CLI config operations and compare-and-swap rules are unchanged.
Direct Runtime API users enabling this soft policy without `contextBytes` use
the fitter's 1 MiB raw envelope; configure the raw limit explicitly when needed.
A Gateway-only budget does not activate that default or new body projection.

The target counts eligible older explicit `read_result` bodies. When their
combined resident bytes exceed it, fitting replaces them oldest-first with
smaller exact reread references confirmed by the existing source/Host owner.
The newest **two complete call groups** are excluded from this advisory pass.
Failed, refused, opaque, unbound and effect results are not soft-trimmed. Missing
read capability does not grant one. References are not evidence that the model
read the hidden body; a subsequent original `read_result` performs that read.

A target is not a second capacity limit. Mandatory content, reference overhead,
or unavailable safe reductions may leave the target unmet. Such a request may
still proceed if it fits the hard budgets. Neither raw nor encoded size may be
increased by the advisory transformation. The existing hard-pressure path may
project additional eligible older groups; its latest explicit read remains
protected. No message or protocol pair is removed, no string JSON is parsed and
rewritten, and no summary is generated by this module.

Every ordinary request checks its final selected messages **and actual tools**
against the Gateway's exact encoder budget before taking a model reservation.
Configured raw-message bytes are checked separately. Restored working inputs
are rechecked too; a smaller current transport envelope fails before dispatch,
without consuming another request. This does not resolve an earlier dispatched
request's unknown result or billing. Byte limits do not estimate model tokens.

`context_fit` observations contain only a schema label, before/after message
bytes and the number of advisory replacements. They are non-authoritative,
contain no source text or credentials, and do not prove quality, token savings,
or that a request was submitted. Observation failure cannot change fitting.

Provider-free regression entry:

```bash
node --test test/context-fitting-v034.test.mjs
```

The fixture tests exercise actual project admission, frozen config, cold Host
readback and resumed Runtime inputs. They do not call a model or qualify the
version for release. A separate authorized ten-task acceptance cohort remains
pending; previous v0.33 unknown requests remain in their original accounting.
