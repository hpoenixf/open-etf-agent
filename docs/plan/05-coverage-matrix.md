# 05 · 基础篇、六层模型与版本覆盖矩阵

> 本表全部是目标映射，不是已实现清单。依据作者提供的基础篇 26 章主题进行摘要对照，不复制书稿正文。出版后的章节变化需重新对账。

## 1. 覆盖的口径

“有界可运行”意味着在声明的 profile、数据与权限范围内有真实代码、运行入口和验证；不是该主题所有高级形态都已实现。“工程实践”意味着通过真实 diff、依赖关系、失败案例和版本历史体现，不应新增一个名为“架构原则”的 Module。

某个版本出现工具名称、一个空目录或一个概念类型，不算覆盖。Lab 的教学入口和原系统的既有证据只能作为参考，不能代替 Open ETF Agent 对应标签的验收。

v1.0 的目标是让这 26 项都有诚实的落点，其中 1—23 是有界运行能力，24—26 是可观察的工程实践。最终发布时必须将“目标”改为实际状态和固定代码入口；不把主题被提及计作实现成功。

## 3. 博客 V3 六层采用同一套产品命名

| V3 层 | 最早的薄路径 | 完整产品主链 | 后续深化 |
| --- | --- | --- | --- |
| L1 任务输入与触发 | v0.1 CLI 请求 | v0.6 CLI/HTTP 接纳 | v0.7 显式后台提交；周期触发不纳入 |
| L2 身份、会话与上下文 | v0.1 受限本地能力与消息 | v0.4 Context；v0.5 Run/Grant；v0.6 本机会话 | v0.8 压缩/记忆；无多人企业账号 |
| L3 Agent 决策与运行 | v0.1 Native Loop | v0.6 Direct/Research | v0.7 Child/后台；完整 Coord 不纳入 |
| L4 工具与领域能力 | v0.1 内建 Tool | v0.2 Skill/MCP；v0.3扩展；v0.4结果与检索 | v0.9 Web/PDF/Python 与 ETF 研究扩展 |
| L5 结果发布与交付 | v0.1 仅终端输出 | v0.6 Publication/SSE/History/Artifact | v0.7 后台与 Child 结果综合 |
| L6 用户界面 | v0.1 CLI | v0.6 Web Chat/引用/下载 | v0.7 按 Run 展示并行交互；v0.8记忆操作 |

v0.6 是首次满足“完整 Web 六层主链”的版本；此前只有可运行的纵向切片。恢复、权限、资源、观测、评估是跨层能力，不另增加第七层，也不把 L6 改称观测层。

## 4. 书稿六层与博客六层不是按行等价

基础篇的教学职责图按知识与工作类别组织；博客 V3 按请求从输入到可见结果组织。本项目公共架构统一使用 V3 命名，教材主题继续按章节映射，不擅自改写书稿。

| 教学职责视角 | 对应 V3 请求视角 |
| --- | --- |
| 交互与研究驱动 | L1 输入＋L3 决策；具体交互界面属于 L6 |
| 上下文与方法 | L2；工具加载及下一回合再次消费发生于 L3/L4 |
| 能力接入与执行 | L3 模型往返＋L4 工具，受 L2 的准入范围约束 |
| 证据与计算 | 主要 L4；结果在 L2 投影、L5 发布时被消费 |
| 交付与连续性 | L5/L6，恢复跨 L2—L5 |
| 观测与评估 | 跨层只读诊断与离线检查，不替代 L6 用户界面 |

## 6. 不为追求覆盖而提前搬入的能力

完整 HIO、自然语言 Coord、持久人类审批、周期/条件 Schedule、多租户账户与额度、跨 Provider 自动容灾、精细交易日历服务、生产投资账本、交易确认与执行、大规模向量检索、跨厂商插件热替换、跨集群恢复，均不作为 v1.0 强制交付项。

这些不意味着永远不做，而是它们不是六层主链成立的必要条件，也不是基础篇的最小有界实现所必须携带的产品复杂度。将来进入新版本仍须通过成熟度、接口局部性和独立运行审查。

## 7. 发布时怎样维护这张表

每次发布只更新本期实际落地行，增加精确版本/路径和验收入口；保留其余 planned 状态。未完成能力要写 missing、partial 或 unavailable 的具体原因。若某接口仅在 mock 中出现，应标为模拟验证，不能写成真实协议/真实子代理/真实沙箱已覆盖。

通过这张表回答“读者在哪个版本能运行什么”，而不是通过章节数量、Owner 数量或测试总数回答“项目是否已经成熟”。
