# 05 · 能力覆盖与版本验收矩阵

> 所有条目均为计划目标。实际发布时补充固定代码版本、运行入口、检查结果与未支持范围；目录或接口名称存在不代表能力已完成。

## 1. 按用户任务组织能力

| 能力组 | 最早版本 / 完善阶段 | 用户可观察结果 | 关键验收 | 明确边界 |
| --- | --- | --- | --- | --- |
| 执行与模型往返 | v0.1 / v0.2 | 完整请求进入同一循环，模型直接回答或调用工具 | 调用匹配、响应完整性、预算、取消、真实失败 | 一种声明支持的协议，不承诺全部Provider |
| 结果与报告取得 | v0.1 / v0.6 | 报告实际保存，引用能回读，附件能下载与重开 | 原字节/版本、来源窗口、读取不重跑研究 | 文件保存不等于Run恢复或实时发布 |
| 方法与外部工具 | v0.2 | 按需读取Skill，通过MCP调用已准入工具 | 真stdio进程、资源路径、协议与模型身份对应 | 不自动安装代码或按方法文字增加权限 |
| 回调与任务分工 | v0.3 / v0.7 | Hook在指定时点工作，批量worker或模型Child交回结果 | 明确回调时点、根预算、独立模型调用、局部失败 | 两种分工分别声明；不做递归代理网络 |
| 取材与上下文 | v0.4 | 查询候选、按候选读原文、ResultRef回读及有界输入 | 查询变化影响实际读页，旧引用不漂移，消息成组 | 默认词法检索，向量/RRF仅后续方向 |
| 长任务材料管理 | v0.5 | 原文可外置、摘要可回退、显式记忆可修订/忘记 | 来源谱系、净容量、忘记后的未来投影排除 | 不自动学习，不承诺删除所有历史副本 |
| 诊断与质量检查 | v0.1记录 / v0.3观察 / v0.6检查 / v1.0复核 | 按Run回查过程，并核对内容、来源、文件与用量 | 真HTTP读取，程序检查与语义判断分开 | 未知不记零，评估不充当运行时发布门 |
| 扩展包与执行连续性 | v0.7 | 可信插件绑定版本，进程中断后沿原身份接续 | 注册回滚、真实新进程、unknown、fence与预算延续 | 无不可信插件沙箱或普遍exactly-once |
| 对话与连续交付 | v0.8 | Web Chat、正文修订、SSE/History、后台研究与短问 | 按Run归属、断线接续、取消、预览/提交区分 | 无完整Coord/HIO、周期任务、多用户协作 |
| 网络、文档与计算 | v0.9 | 有界Web读取、真实PDF解析、隔离Python派生产物 | 实际HTTP/PDF/容器、来源/输入/代码/输出关联 | 扫描件/OCR全覆盖和宿主任意代码不支持 |
| ETF只读研究 | 早期合成计算 / v0.7扩展包 / v0.9完整案例 | 资料、计算、解释和报告交接可核对 | 显式单位/币种/截止日/舍入，原输入可复算 | 合成数据；无真实持仓真值或交易执行 |
| 可维护演进与发布 | 全阶段 / v1.0收口 | 独立标签可运行，新增能力能替换或移除 | 实际diff、删除旧路径、公共API、环境与迁移 | 不用模块或检查数量证明成熟 |

这些能力可以共享存储和基础设施，但事实归属不同。合成演示、真实机制和模型质量分别验收，不能合成一个含糊的“通过”。

## 2. 六层请求链的逐步形成

| 层次 | 最早的最小路径 | 主要完善版本 | 责任交接 |
| --- | --- | --- | --- |
| L1 任务输入与触发 | v0.1 CLI | v0.8 HTTP与显式后台提交 | 接收请求，不预替模型判定研究策略 |
| L2 身份、会话与上下文 | v0.1本地能力范围 | v0.4材料投影、v0.5记忆、v0.7持久身份、v0.8会话 | 提供获准材料与方法，不从摘要重建权限 |
| L3 Agent决策与运行 | v0.1 Native Loop | v0.3 Child、v0.7接续、v0.8后台 | 模型提出动作，Host推进合法执行 |
| L4 工具与领域能力 | v0.1内建读取/计算 | v0.2MCP、v0.4结果、v0.9研究工具 | 返回真实结果和缺口，不认证整体结论 |
| L5 结果发布与交付 | v0.1文件保存 | v0.6阅读/下载、v0.8Publication与事件 | 内容提交、文件与投递状态分别保留 |
| L6 用户界面 | v0.1 CLI | v0.6只读reader、v0.8Web Chat | 按Run和版本呈现，不猜测归属 |

v0.6完成可独立使用的报告研究闭环；v0.8首次打通完整Web主链。六层是请求视角，不是六个进程；观测、评估、授权、资源和恢复跨层工作，不新增第七层。

## 3. 三种运行配置与里程碑

| 配置 | 主要能力 | 计划完成点 | 不能省略的检查 |
| --- | --- | --- | --- |
| 基础配置 | 有限循环、方法/工具、分工、材料/记忆、报告与检查 | v0.6 | 安装后离线示例、显式live入口、来源和文件真实读回 |
| 工程配置 | Plugin、持久执行、Publication、Chat、后台 | v0.8 | 真实进程故障、并发归属、持久版本和SSE接续 |
| 研究配置 | Web、PDF、隔离Python及ETF扩展 | v0.9 | 实际解析/容器/HTTP，单列支持环境 |
| 发布收口 | 公共API、配置资格、兼容边界和阅读入口 | v1.0 | 最终候选、固定标签、获准语义复核及限制声明 |

配置按需安装，但对外声称支持的配置必须真实验证。缺Docker或外部服务时明确不可用，不静默换成mock后算通过。

## 4. 暂不承诺的能力

多租户IAM、动态撤权传播、完整HIO/Coord、周期/条件调度、自动长期学习、跨Provider无损切换、通用向量平台、扫描PDF/OCR全覆盖、任意第三方代码安全执行、交易账本/执行、多节点容灾和普遍exactly-once。

向量、混合召回与RRF是按检索质量再评估的方向，不是使用基础版本的安装前提。恢复、Plugin和后台保留在既定工程阶段，不要求第一版先实现。

## 5. 发布时回填什么

逐项写明能力ID、计划版本、实际实现级别、运行入口、固定SHA、验证环境和未覆盖项。`planned`、`implemented`、`verified`、`released`分开；语义检查保留独立的reviewed/unreviewed状态。公共矩阵只解释本仓库可提供的能力，不借其他项目的记录签发本项目资格。
