# 02 · v0.6—v1.0：从可恢复研究到完整交付

> 状态：全部为规划。命令和路径是实施目标；本文件不证明这些功能已经存在。前置为 [v0.5 及之前的已验收能力](01-roadmap-foundations.md)，不得通过跳过前置故障路径来抢先宣布本期完成。

## v0.6 · Publication、Artifact 与 Chat：第一次打通 Web 六层主链

### 新增内容

新增核心 K8 Publication。增加薄 HTTP/Conversation 入口、轻量 Web Chat、Artifact Adapter 与用户事件交付 Adapter。CLI 和 HTTP 使用同一套 Runtime，不为网页再造执行循环。

默认本机单用户、绑定 loopback；有明确本机会话令牌、来源检查和写操作防护，不宣称只绑定 localhost 就能替代鉴权。密钥只留服务端，不进入浏览器、日志、History 或导出文件。Web UI 可以使用原生 TypeScript 与最小构建工具，不在本期引入完整管理后台。

### 六层的实际落点

| 层 | 本期实际行为 |
| --- | --- |
| L1 任务输入与触发 | CLI/HTTP 接收请求，生成请求与消息身份 |
| L2 身份、会话与上下文 | 服务端确定本地主体，创建/关联 Conversation 与 Run，准备原授权和材料 |
| L3 Agent 决策与运行 | 同一 Native Loop 直接回答或多轮研究，不以关键词硬编码研究语义 |
| L4 工具与领域能力 | 内建、MCP 与领域扩展执行；结果与引用由原模块管理 |
| L5 结果发布与交付 | Publication 接纳正文，提交修订；通过 SSE/History/附件提供交付 |
| L6 用户界面 | 输入、状态、Markdown、引用回读、下载与刷新后还原 |

### 发布与文件的区别

Publication 管 `runId + publicationId + revision` 的内容状态：候选、可见预览、耐久提交。Artifact 管文件的字节身份、媒体类型、哈希与访问范围。生成文本、提交数据库、发送事件、浏览器绘制不共享一个 completed 标记。

正文修订与对应持久交付事件在同一个 SQLite 事务内写入；事件流用单调游标和稳定 eventId 做接续/去重，不声称网络 exactly-once。UI 依据 Run 和 revision 接纳事件，不能用“最后一条消息”猜归属。

预览可以显示，但必须标明未保存；History 只重放耐久提交版本。先支持完整正文修订，再支持有界预览/追加，不承诺任意多人协同编辑。工具或模型原始载荷不能直接作为公共 SSE 转发。

附件先支持 Markdown、CSV 与可信生成的 HTML/SVG。文件输出写临时文件、校验内容、原子改名后登记；跨数据库和文件系统不存在统一事务，靠内容身份、幂等登记和可恢复的孤儿清理收敛。HTML/SVG 不能在应用主 origin 中无隔离执行；优先下载，预览使用隔离与禁脚本策略。

### 演示与验收

新增拟定入口 `npm run web`。用户提交比较请求，看到工具进度、正文与引用，下载报告；刷新后仍能回读同一修订。允许新消息带已发布上下文开始新 Run；本期不做在途 Coord 或自动抢占研究。

必须验证：相同发布操作重试不增加第二份修订；SSE 断线后接续不重复消息；HTTP 连接断开不被当作用户取消；无效引用只影响相关引用/声明，不抹掉独立成立的正文；附件失败不把已有正文清空；非法路径不能下载；浏览器不执行资料中的 HTML/脚本；恢复后的发布仍绑定原 Run。

文章主题：“模型已经回答，为什么用户还可能什么都没拿到？”展示同一答案从候选到提交、推送和回读的完整过程。

## v0.7 · Subagent 与 Background：同一执行语义，两个不同维度

### 必须区分的概念

Subagent 解决研究分工；后台 Worker 解决运行与页面连接分离。它们不是同一个模块，也不能用 `Promise.all(readFile)` 冒充独立 Agent。

不增加 K1—K8 核心责任模块，增加 Child 执行扩展和后台 Worker 宿主。复用 K1 的可嵌入循环及原持久化契约，不复制第二套 runtime.ts。

### Child 最小范围

Main 可以委派一个有明确任务、允许材料、工具子集及资源上限的 Child。Child 独立调用模型并有局部上下文、取消和结果身份；最多一层委派，不做递归多 Agent 网络。并行上限是本地有限配置，不是新的总预算。

Root 拥有总消耗；Child、重试和辅助模型调用都计入同一根预算。Child 能力不得超过 Root 原授权，不能独立向用户发布。Main 消费包含发现、限制与 ResultRef 的交接包；不能把 Child 摘要说成 Main 已读原文。

持久化 Child 的委派身份、配置绑定、已结算动作和交接结果。Main 重启不重复派发已经完成的 Child；进行中的模型请求存在未知结果时遵守 v0.5 的 unknown 语义。Child 失败只结束自己或报告局部缺口，不自行终结兄弟或 Root。

### Background 最小范围

独立进程从本地 SQLite 领取 Run，持有 lease/fence，执行、续租、结算和退出。浏览器或 CLI 客户端关闭不终结后台研究；显式 cancel 才改变其生命周期。父进程退出、日志句柄、工作目录与凭据传递均需具体处理，不以 Node 的 detached 选项存在作为验证。

默认支持一个后台 Research，以及可并行的短 Direct 交互；所有消息按独立 Run 关联。共享 Provider 并发采用有界本地准入，不做跨集群容量平台。短问不能读取后台未发布的内部材料。初期只支持 inspect/cancel 和终态后的显式新 Run 继续，不做自然语言在途纠偏、HIO 或周期任务。

### 端到端验收

1. Main 将两版资料的核对交给两个真正调用模型的 Child，汇总引用与分歧；工具并行和模型 Child 分别留证。
2. 一个 Child 失败时另一份有效结果仍可交付，Root 明确覆盖缺口。
3. 后台任务在浏览器关闭后继续；重开能够看到同一 Run 及其已发布版本。
4. 后台 A 未完，短问 B 可以结束；A 的后续事件仍属于 A。
5. Root/Child 总预算不被拆成数个独立满额预算；取消 Root 后不得再派发 Child 动作。
6. 进程在 Child 完成后、Main 消费前中断，新进程采用原交接包，不重复研究。

拟定入口：`npm run start -- background --case delegated-comparison`，以及已有 inspect/cancel/resume。文章分别解释“把工作分出去”和“让工作离开连接继续进行”，避免用一个泛化异步模块掩盖区别。

## v0.8 · Compaction 与 Memory：保留事实，改变下一次输入

### 为什么分开

Compaction 减少本次执行需要携带的历史；Memory 为以后任务保存明确偏好。两者不能合并成一个“智能记忆层”，也不能把摘要升级成原始证据。

### Compaction 子集

只压缩已结算且可回读的历史区间；保留原用户请求、未结算调用、结果身份、来源窗口及已提交正文。摘要由模型产生，采纳时记录输入区间、来源、摘要版本和资源消耗。没有容量收益或摘要失败时保留原材料；不能借压缩失败拒绝已有正文。

压缩模型请求纳入根预算并可取消。恢复读取已经采纳的摘要及其谱系，不重新生成后冒称同一 checkpoint。上下文中明确区分原文与派生摘要。实现只需支持受控的连续压缩，不先做泛化多级记忆系统。

### Memory 子集

显式 opt-in 的本机偏好记录，提供 list/search、save、revise、forget。保存内容应是用户批准的稳定偏好，而非自动抓取整段聊天；模型可提出建议，真正写入由用户显式操作确认。记录稳定 ID、修订、来源和失效状态。

用户忘记后，新的上下文投影不能从旧摘要、缓存或已保存 History 重新注入该记忆。记忆撤回和原始审计记录保留/删除的政策分别写清；不得承诺未执行的物理全盘删除。旧答案历史与未来上下文不是同一个读取面。

Memory 不保存 API Key、交易授权或“当前持仓真值”；不向其他用户共享，不授予原 Run 新工具权限。默认不做自动语义学习、长期用户画像和外部向量库。

### 验收

长任务中控制压缩触发；压缩前后均可读取原文及引用；低质量或空摘要能回退；摘要失败不导致额外无界模型调用；重启采用既有摘要；偏好在新任务生效；修订与忘记在后续投影中生效，旧缓存无法使其复活；Root 与 Child 的材料消费范围不被压缩扩大。

拟定演示：`npm run demo -- --case compact-and-reread`、`--case explicit-memory`。与 v0.7 使用相同任务比较模型输入和交付，不用“token 更少”单独证明答案更好。

## v0.9 · Web、PDF、Python：研究工作台走出内置文本

### 分为默认 profile 与 research profile

默认 profile 继续是无需云服务、无需 Docker 的合成资料研究；安装依赖后可离线运行。research profile 追加解析器与隔离执行环境，不使所有读者为可选能力安装一整套平台。

research profile 不能只有 mock。发布验收要在明确支持的环境中运行本地 HTTP fixture、真实合成 PDF 文件和真实容器内 Python 计算。外部网站及云搜索的 live 检查单列；fixture 成功不证明公网读取一定成功。

### Web Adapter

先实现有界 URL 抓取和页面正文读取；搜索作为可替换工具，可由用户配置的 MCP 服务提供，不依赖一个私有搜索网关。记录原 URL、最终 URL、获取时间、内容版本及覆盖范围。

网络访问须经显式准入，限制协议、大小、超时、重定向、目标地址及内容类型。逐跳校验目标，避免通过跳转或 DNS 地址变化访问内部地址。测试 fixture 的本机地址例外只能存在于测试配置，不进入发布默认策略。网页中的指令一律作为资料内容，不能改变 Host 的权限与方法配置。

### PDF Adapter

使用锁定解析器提取真实 PDF 的页文本和基本表格位置，保留原文件哈希、页码与缺失状态。先支持有文本层的合成 PDF，不把“没有报错”当作全文完整读取。扫描 PDF、多模态/OCR、复杂跨页表格可以明确 unavailable，不得伪造页覆盖。

### Python Adapter

默认不开放任意宿主代码执行。经用户显式启用的容器 Adapter 执行审核过的计算脚本或本次获准代码；默认禁网、非特权、限制 CPU/内存/PID/运行时长，输入只读挂载，输出目录受限，不传宿主密钥、不挂 Docker socket。子进程或虚拟环境本身不能标为安全沙箱。

容器镜像与依赖固定版本/摘要；预拉镜像所需网络与任务执行的禁网状态分开。保存输入 ResultRef、代码摘要、执行回执和输出 ArtifactRef；禁止把程序退出码 0 当作公式、数据口径或投资结论正确的证明。

### ETF 领域案例

用合成 ETF 报告、行业权重和费用数据完成一次有来源的集中度/费用比较。计算实现使用显式十进制、单位和舍入；模型解释适用范围及缺失数据。主文与附带 CSV/HTML 同时可取回，不能把某项文件导出失败升级成整项研究没有答案。

### 验收

SSRF/重定向/体积限制；网页拒绝与局部缺失；PDF 原页与引用一致；不支持扫描件时诚实说明；Python 越界路径、联网、超时、超额输出被限制；未知文件效果可收敛；输入数值能独立复算；HTML/SVG 不突破前端隔离；缺 Docker 时返回 research profile 的 unavailable，不伪装执行成功。

拟定入口：`npm run demo -- --case research-workbench --profile research`。该 profile 需通过自己的发布资格，不能在全量验收时静默跳过。

## v1.0 · 稳定接口、可观测性、评估与完整覆盖声明

### 不是“再堆一批功能”

冻结已经验证的小型公共面：启动一次 Run、注册受信任扩展、提供模型/工具 Adapter、订阅允许的用户事件、读取发布结果。内部持久化实现与调度细节不全部变成公共 API。稳定性只针对本项目明确支持的环境、模式和契约。

补齐诊断/评估工具，不把它们变成新的运行时批准者。基础事件与回归检查从 v0.1 就存在；这里统一只读回查、覆盖声明和对外可复现记录。

### Observability

从 runId 关联模型请求、工具调用、结果、Child、发布版本与 Artifact。输出使用量、延迟、失败类型和覆盖缺口；未返回的 token、费用或 Provider 内部信息保留 unknown。默认只记录安全元数据；正文捕获需 opt-in、脱敏和保留策略。

`observe` 不发起模型调用，不改恢复游标、不重新授权、不重签发布成功。外部 Trace Adapter 可选，离线项目不依赖 Langfuse 账户或云端遥测。

### Evaluation

固定输入、fixture 版本、模型配置和交付对象。分别报告工程交付、来源支持、计算正确性、任务符合度、成本/用量。不要把“Run ended”“附件可下载”和“内容正确”合成一个成功率。

建议最终候选进行两模型、四至八项任务的公开可复现运行；至少覆盖事实差异、条件限制、数值复算、宽泛报告。小样本仅用于检查本次支持范围，不能据此宣称一般模型优劣或生产准确率。保留失败、重试、版本与未评审项；最后的发布声明所依赖任务需要作者或指定审阅者逐项签审。

模型名称、账号、密钥、付费范围不由本方案授权。实现时使用用户已经批准且可获得的服务，明确费用上限；不能用替身记录填补真实模型验收缺口。

### 稳定发布条件

- 最新候选独立安装与默认 demo 通过，核心能力无私有仓库/私有包依赖。
- research profile 在声明的平台真实运行；不支持的平台及能力有明确限制。
- 原有关键故障路径仍成立，包括冷恢复、unknown、取消、Child 结算、SSE 接续和附件失效。
- 26 章映射中的每项给出已实现/有界实现/未覆盖，而非仅链接空目录。
- 所有公开入口及示例扩展只依赖公共 API；至少一个扩展能够替换或移除而不修改循环。
- 代码来源、第三方许可、公开数据、密钥与日志完成审查；选定许可证后再正式发布代码许可。
- README、版本标签、运行环境、已知限制、文章入口和实际代码一致。

任何必需项未完成就保持候选版本；不得为了满足 v1.0 日期把未稳定机制移入默认内核。若最终主动缩小范围，必须同时修改覆盖矩阵和版本声明，不能维持“已全覆盖”的宣传。
