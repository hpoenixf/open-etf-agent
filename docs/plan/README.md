# Open ETF Agent：可运行的版本演进方案

状态：**提案，等待评审**。编制日期：2026-10-26。本文及关联文档只定义目标与验收，不表示任何运行版本已经实现、测试或发布。

## 1. 决策摘要

项目不从一个功能完整的框架开始，而从一个能独立运行的 Native Agent Loop 开始。之后每一期解决一种新的真实问题，保留完整代码、示例、验证方式和演进说明，最终形成覆盖六层请求链及基础篇主要能力的 v1.0。

核心承诺是：**每个版本都能单独 checkout、安装和运行；读者能比较相邻版本，看到新增能力带来的必要结构变化，以及被删除的旧实现。**

采用十个里程碑：v0.1—v0.9、v1.0。每期一个 `phase/vX.Y` 分支，每次发布一个 `vX.Y.Z` 标签。分支保留该期功能范围，标签固定某次已经验证的代码。`main` 只接纳完成当前范围验收的阶段；本方案 PR 是文档准备，不是 v0.1 发布。

### 相比此前讨论的调整

- 原先一次性交付“8 个核心模块＋Skill/MCP＋六层界面”的设想，改为从 **3 个核心模块**逐步演进。不是把旧方案全部塞进 v0.1。
- Skill 与 MCP 保留在最早一轮扩展 **v0.2**，不是取消或推迟到项目末期。这是对“v0.1 极简”的取舍。
- v0.6 首次打通完整的 Web 六层主链；v0.7—v0.9深化协作、长期上下文和研究工具；v1.0收敛公开接口、验证和阅读入口。
- “成熟”描述的是所采用机制的来源及本版本实际验证结果，不能从原系统或 Lab 的成功记录自动继承。
- 一到两天只可作为极小起点的集中开发窗口，不作为全部版本或稳定性验收的承诺。发布按条件推进，不按日历强行打标签。

## 2. 仓库定位

| 项目 | 本方案中的角色 | 不承担的责任 |
| --- | --- | --- |
| ETF Agent | 提供成熟设计认识、已知故障类型和可公开的行为约束 | 不向开源仓库同步全部实现或每项新功能 |
| Agent Harness Lab | 基础篇的教学配套与机制示例 | 不作为 Open ETF Agent 的运行依赖，不被本计划重写 |
| Open ETF Agent | 连续演进、可运行、可扩展的独立实现 | 不复制私有仓库历史，不承诺完整生产平台等价 |

使用两条案例线。通用主线是两版合成文档的比较，方便读者核对原文；领域主线是合成 ETF 资料与组合的只读分析，用来检验领域能力能否留在扩展中。所有数据均需明确标注合成，不接入真实个人持仓或交易。

## 3. 十个版本一览

“核心数”只统计下文 K1—K8 的运行时责任模块；适配器、可选能力和 UI 不混入该数字。它不是总模块数，更不能与原系统的 Owner 数量直接比较。

| 版本 | 本期主题 | 新增核心责任 | 累计核心数 | 用户可见的变化 |
| --- | --- | --- | ---: | --- |
| v0.1 | 极简可运行 Agent | K1 Runtime、K2 Gateway、K3 Tool Host | 3 | CLI 中完成读取、计算和回答；同一循环支持替身与真实模型 |
| v0.2 | 方法与外部工具 | 无；增加 Skill / MCP 适配器 | 3 | 按需读 Skill，通过真实 stdio MCP 往返读取资料 |
| v0.3 | 可组合扩展 | K4 Extension Host | 4 | 一个受信任扩展包贡献 Tool、Skill、Hook，无需修改循环 |
| v0.4 | 研究材料与上下文 | K5 Context、K6 Research Result | 6 | 词法检索、原文回读、ResultRef、引用和有界模型输入 |
| v0.5 | 可恢复执行 | K7 Session & Recovery | 7 | SQLite 持久状态、冷进程恢复、未知效果停留 unknown |
| v0.6 | 可交付的六层主链 | K8 Publication | 8 | Web Chat、正文版本、SSE、History、报告及附件下载 |
| v0.7 | 子代理与后台任务 | 无；增加 Child 与 Worker 能力 | 8 | 真正独立模型子任务、共享根预算、后台研究和取消 |

| v1.0 | 稳定公共面与可核对交付 | 无；完善诊断与评估工具 | 8 | 冻结小型公共 API，覆盖声明、工程证据、真实任务复核配套 |

## 4. 设计约束

### 小内核不等于缺少安全底线

v0.1 就要具备明确工具表、结构参数检查、调用身份、错误回传、总轮数上限、超时和取消。持久化前不承诺恢复；网络工具出现前不预造网络治理；出现外部副作用时不能用简单重试掩盖未知执行结果。

### 可扩展不等于把所有控制权交给 Hook

模型判断研究策略；Host 执行获准动作；Result 保存结果身份；Publication 处置用户正文；Recovery 保留已发生的事实。扩展只获得所需的窄接口，不得到一个包含整个 Runtime、数据库和内部状态的万能 context。

### 只在需求出现时引入抽象

v0.1 不预建八个空目录、不建全局事件总线、不建通用工作流 DSL、不建插件市场或多租户平台。模块增量以实际行为和可替换实现为依据。接口复杂度、依赖传播和升级局部性比文件数或代码行数更重要。

### 本期完成不是下期 stub 已经存在

每期发行内容只有本期支持的能力。README 可以描述未来路线，但运行界面不得展示没有实现的按钮；命令不得静默降级后返回“成功”。未来目录、命令与类型只出现在设计文档中，不提前生成占位实现。

## 5. v1.0 的边界

v1.0 目标是一个**本机单用户、CLI＋Web、可接真实模型的研究 Agent**。默认示例依赖合成数据与确定性网关；显式 live 模式使用用户自行配置的服务。Web/PDF/Python 提供独立 research profile，其环境与验收必须另行声明。

目标覆盖基础篇 26 章对应的主要机制，其中架构原则与研发演进通过代码组织、测试及相邻版本差异体现，不各建一个运行时模块。覆盖按“实现范围、运行入口、验证记录、未覆盖部分”说明，不给一个混合了规划与实现的百分比。

v1.0 不承诺：交易执行、金融生产正确性、多人 SaaS、跨组织授权、任意第三方插件安全执行、多节点容灾、任意外部效果 exactly-once、完整 HIO/Coord、周期调度、自动长期记忆、向量检索平台或全部 Provider 协议兼容。
