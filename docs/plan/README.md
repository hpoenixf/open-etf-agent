# Open ETF Agent：版本演进方案 R2

状态：**提案，全部运行版本仍为 planned**。修订日期：2026-10-26。本次依据作者新提供的《从零构建 Agent Harness · 入门篇》重排原方案；只修改方案 PR，不实现产品、不发布版本。

## 1. 本次先纠正基准，再调整顺序

教材基准是 `agent-harness-beginner.pdf`，209 页、21 章，学习修订稿 2026.10；书内代码讲解锁定 Lab `c79979a`。之前使用的 26 章完整稿不再作为入门范围。PDF 第 4 页把完整恢复、插件装载和后台运行留给进阶稿，第 6—14 页则先完成来源明确、实际保存的报告。详见[源文件对照](08-beginner-source-review.md)。

因此修订的不是“26 改成 21”一个数字，而是三项设计：**报告从 v0.1 就可取得；入门能力不再等待恢复/插件/后台；入门覆盖和产品扩展分别记账。** 保留用户原要求：每期一个分支、每版独立运行、成熟机制逐步进入、最终尽量覆盖此前六层产品构想。

## 2. 三种来源，四种交付性质

| 标记 | 含义 | 本计划如何使用 |
| --- | --- | --- |
| B | PDF 中的入门实践与最低理解目标 | 前六期完成有界实现；不是复制教材源码 |
| E | PDF 明示的接口设计、选读或后续深化 | 标为扩展，不把“讲到了”当成 Lab 已实现 |
| P | 本次对话此前提出的产品/工程能力 | 后半段保留，不倒过来改写书的必修范围 |
| G | 架构判断与工程演进实践 | 用真实 diff、替换、失败诊断体现，不新建运行模块 |

这些是需求来源标记，不是实现状态。每项仍需单列 planned、implemented、verified、released；一个 B 项也可能尚未实现，一个 E/P 项也可以经验证后进入版本。

**v0.6：入门主线里程碑。** 21 章的入门目标都有可运行或工程实践落点，不表示每个“未来扩展”也完成。

**v0.8：Web 产品六层主链里程碑。** CLI/HTTP 输入、会话/授权/上下文、Agent 运行、工具、正式发布/交付、Web 界面全部接通。它与书中的六个职责阅读切面不是同一套层号。

核心数仅统计架构文档的 K1—K8；报告文件工具、Child、Memory、解析器和 UI 依然是有成本的模块，不能藏在“八个核心”里。数字是当前分组结果，不是必须凑齐的指标。

## 4. 一份贯穿案例，而不是十个互不相关的 Demo

用独立编写、明确可再分发的两版合成文档贯穿所有版本。共同问题始终保留对象、版本、条件和报告要求。后续版本增加能力，但仍能运行早期问题；对比时改查询或资料，结果应沿实际读取变化，不能固定读几页后声称检索生效。

从 PDF 第 183 页提炼四种验收类型：功能差异与共同限制、免费版条件、增量与倍数、报告保存/取得/重开。具体 fixture 可以独立重写，不复制私人书稿。v0.1 就保存文件并核对字节；HTTP 下载仅从 v0.6 起成为要求。

ETF 是第二条领域案例，用合成只读数据验证扩展和数值来路；不得把个人组合、真实账户或交易引入默认样例。Lab 不是运行依赖，书稿也不随代码发布。

## 5. 极简仍须保留的底线

从第一版起保留原用户请求、调用身份、工具输入检查、限定来源和输出目录、有限预算/超时/取消、真实失败和保存回执。日志可以先是 JSONL，资料可以先是文件，保存可以先是普通 Tool；不因需要文件持久化就强制先建 Recovery。

没有恢复能力的版本，进程中断后明确不能续跑。重新打开已保存报告是读取，不是研究恢复。请求已经发出却没有确定回执时保留 unknown，不把未知当未执行自动重试。

不预创建八个空模块、不用通用事件总线包办所有能力、不让 Hook 接管授权/终态/发布、不把安全底线留给提示词。

## 6. “尽量覆盖”不等于抹去范围差异

v1.0 保留原构想中的 Skill/MCP、Plugin/Hook、Result/引用、Recovery、Publication、Web UI、Subagent/后台、Compaction/Memory、Web/PDF/Python、观测/测评与 ETF 扩展。它们分为默认入门配置、显式工程配置及研究环境配置；按各自真实证据发布。

向量/混合检索、RRF、自动长期学习、跨账户授权、完整 HIO/Coord、周期任务、多机容灾、交易执行仍可保留设计或后续路线。没有实现的项必须写明未覆盖；不能宣称“全书所有设计都已实现”。
