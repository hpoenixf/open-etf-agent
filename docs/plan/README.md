# Open ETF Agent：分阶段可运行演进方案

状态：**提案，全部运行版本仍为 planned**。更新日期：2026-10-26。本方案定义版本范围、接口演进与验收条件，不是已发布功能清单。

## 1. 项目主张

先交付一份能打开、能核对来源的结果，再逐步增加方法加载、工具接入、分工、上下文管理和工程可靠性。复杂能力有明确需求才加入，旧实现被替换后及时退出；不在 v0.1 预建完整框架。

每一期都保留完整可运行代码。读者可以停留在任一已发布版本，也可以比较相邻版本，看到新增能力为何需要改变结构，以及哪些结构不需要改变。只引入经过验证的成熟机制，并对新的独立实现重新验证。

## 2. 两个阶段与十个版本

| 版本 | 用户可见增量 | 阶段 | 核心责任分组累计数 |
| --- | --- | --- | ---: |
| v0.1 | 读取、模型/工具往返、带出处的 Markdown 文件和运行记录 | 基础研究 | 3 |
| v0.2 | Skill 按需读取、真实 stdio MCP、模型流接收 | 基础研究 | 3 |
| v0.3 | Hook、受限并行 worker 与独立模型 Child 的分别演示 | 基础研究 | 3 |
| v0.4 | Context、词法检索、原文回读、ResultRef 和引用 | 基础研究 | 5 |
| v0.5 | 原文外置与派生摘要、显式 Memory 保存/修订/忘记 | 基础研究 | 5 |
| v0.6 | 报告阅读、附件下载、observe/evaluate 与格式扩展 | 基础研究 | 5 |
| v0.7 | 可信 Plugin、SQLite、Checkpoint/Recovery 和未知效果处理 | 工程扩展 | 7 |
| v0.8 | Web Chat、Publication、SSE/History、后台 Worker | 工程扩展 | 8 |
| v0.9 | 有界 Web、真实 PDF、隔离 Python 与合成 ETF 案例 | 研究工具 | 8 |
| v1.0 | 稳定公共面、运行配置验收和实际覆盖声明 | 发布收口 | 8 |

**v0.6 是基础研究闭环里程碑**：用户可以运行研究、核对来源、取得文件并查看执行记录。无需具备后台运行和完整冷恢复，也能独立使用。

**v0.8 是 Web 六层主链里程碑**：任务输入、身份/会话/上下文、Agent 决策运行、工具领域能力、结果发布交付、用户界面全部接通。恢复、权限、资源、观测和评估跨层参与，不再增加额外的层。

核心数只统计 [K1—K8](03-architecture-contracts.md) 的责任分组。Child、Memory、Report、Artifact、适配器和 UI 仍是实际模块，不能把它们的维护成本藏在“八个核心”里。数字不是质量指标，接口与依赖方向才是。

## 3. 同一案例贯穿演进

独立编写两版合成资料，持续使用同一基础比较任务。每期保留共同任务，再加入一个新能力案例与一条失败路径。改变查询或资料后，实际读取与结果应相应变化；固定脚本不能冒称模型主动研究或检索已经生效。

回归覆盖事实差异、适用条件、数值关系、保存与重新取得结果四类问题。具体问题、资料、数值和预期在本仓库独立定义。v0.1 核对本地文件，v0.6 再核对 HTTP 下载与重开；未提供的入口不计为通过。

合成 ETF 是第二条领域案例，用于检查确定性计算、来源关联和扩展隔离。所有资料明确标注合成及适用范围，不引入真实个人持仓、客户记录或交易写入。

## 4. 能力范围与证据状态分别记录

| 范围 | 约定 |
| --- | --- |
| 基础配置 | 从有限工具循环到可核对报告；安装依赖后可离线运行默认示例 |
| 工程配置 | 插件、持久执行、Web 发布与后台；依赖本仓库真实进程与存储验证 |
| 研究配置 | Web/PDF/Python 等额外工具；单列环境、权限和验收 |
| 后续方向 | 向量/混合检索、RRF 等可再评估；未实现不列作已支持 |

范围不代表状态。计划、代码实现、机制验证、真实模型语义复核和正式发布分别记录。不能用默认示例通过证明外部服务、沙箱或金融结论正确。

## 5. 极简实现仍要保留的合同

从第一版起保留用户原文、调用身份、结构参数校验、限定材料/工具/输出目录、有限资源、取消和真实失败。保存回执说明文件是否产生；模型口头说完成不替代实际效果。

结果持久化、供未来任务复用、原 Run 跨进程恢复是三种不同能力。早期文件可回读不表示原任务可恢复；未知效果不解释为未执行，不能自动重试所有外部调用。

扩展使用窄接口，不接收万能 Runtime context。Hook 不接管其他模块的权限或终态；Context 是工作视图，不改写来源、执行和用户要求；Publication 管正文，Artifact 管实际文件。

## 6. 发布与维护

采用 `phase/vX.Y` 阶段分支与固定 `vX.Y.Z` 标签，累计演进而非十套互相复制的实现。每个已发布标签具备完整源码、锁文件、示例、命令和必要检查。发布后的旧阶段冻结功能，只做必要安全和运行修复。

每期说明新增行为、被替换代码、兼容边界、验证范围与未完成事项。文章绑定固定标签和相邻 diff，不依赖 main 的最新内容。尚无实现时不预打标签、不生成占位功能。

## 7. v1.0 边界

目标是本机单用户的研究 Agent，CLI 与轻量 Web 共用运行核心，默认示例无模型密钥，live 模式显式启用。成熟能力按需加载，不为所有用户默认安装全部研究环境。

不承诺交易执行、多租户 IAM、完整 HIO/Coord、周期/条件调度、自动长期学习、通用向量平台、多节点容灾、所有 Provider 协议或任意外部效果 exactly-once。能力未成熟时保持候选或缩小声明，不因版本名降低门槛。
