# 01 · v0.1—v0.5：从工具循环到可恢复研究

> 状态：全部为规划。下列命令、路径与输出是各版本必须实现的目标，不是当前仓库已有入口。每一期继承上一期已发布能力，且不需要安装、启动或 checkout 上一期才能运行。

## 通用案例与版本合同

主案例始终是同一组自行编写的合成资料：产品手册 A/B、各自版本与页码、可计算的数值差异。保留一个简单问题作为所有版本共同的回归：“比较两版导出上限，给出差值、倍数和依据。”

第二条案例使用合成 ETF 数据，所有文件注明 `synthetic: true`、币种、单位与 `dataAsOf`。它用于测试工具替换及领域隔离，不向用户输出真实投资建议。

每期都必须具有：该期 README、固定依赖与运行环境、确定性 demo、真实模型入口、自动检查、明确错误退出、演进说明和范围限制。替身与真实模型使用同一个 Runtime 和 Tool Host；替身只替换模型响应，不另写一套演示工作流。

拟统一入口：`npm ci`、`npm run build`、`npm test`、`npm run demo -- --case document-compare`。真实调用使用显式 `npm run start -- --live --case document-compare`。环境与命令的准确形式由各期实现锁定；不存在的未来子命令不得提前出现在该期帮助列表中。

## v0.1 · 一个真正可运行的最小 Agent

### 要解决的问题

把“模型说要读取”接成真正的工具执行，再把回执送回模型，最后得到回答。起点不是一个写死步骤的文档脚本，也不是预先装好数据库、插件和网页的框架。

### 范围

三个核心 Module：K1 Runtime、K2 Model Gateway、K3 Tool Host。另有薄 CLI 入口，不单列为核心。单任务、单执行进程、内存状态；工具先串行执行。

- Runtime：Native tool loop、有限轮数、工具调用总量、超时、AbortSignal、明确终态及工具错误回灌。模型可直接回答，也可调用工具；不需要独立意图分类模型。
- Gateway：一个明确支持的工具调用协议、非流式 JSON 往返、确定性替身和真实服务 Adapter。保留工具调用 ID，校验响应完整性；不声称支持所有“兼容”端点。
- Tool Host：显式工具注册、成熟 Schema 校验器、运行时参数校验、获准工具集合、调用身份及结构化结果。工具注册时同时绑定描述与执行函数，避免两份工具表漂移。
- 最小工具：读取指定 fixture 文档，以及只接受结构化数值参数的确定性计算。不能给模型一个任意 `eval`、shell 或自由路径读取工具。
- 输出：终端 Markdown 答案；展示资料 ID/页码，但不冒称已有完整 Citation/Publication 系统。

建议文件起点是 `src/runtime.ts`、`src/model.ts`、`src/tools.ts`、`src/cli.ts`，辅以 fixture 和测试。文件可按实现需要调整，不以固定行数或目录数验收。

### 不做

Skill、MCP、Plugin、Hook 注册体系、数据库、恢复、Subagent、Memory、RAG、Web UI、后台 worker、交易或通用工作流。前述能力只在路线文档出现，不放入空实现。

### 行为合同

一次工具调用必须对应唯一的 Host 调用身份。未知工具和无效参数不执行；工具失败回到模型作为失败观察；取消后不启动新动作，晚到结果不得把 cancelled 改回 completed。正常工具错误和整个 Run 终态分开。

达到资源上限后返回已有可用结果和限制说明，不能无界重试。模型文本不能改变获准工具清单、预算或代码执行范围。没有持久化就明确声明进程退出后不可恢复。

### 验收

| 场景 | 必须观察到的结果 |
| --- | --- |
| 不需工具的问题 | 同一循环直接给出回答 |
| 两次读取＋计算 | 每个调用与回执匹配，原数值和计算结果可核对 |
| 未注册工具／错误参数 | 派发前拒绝，工具没有发生执行 |
| 工具业务失败 | 模型得到真实失败，有界重试或说明缺口 |
| 截断的模型响应 | 不把不完整参数交给工具 |
| 达到上限／用户取消 | 有界退出，终态与错误原因明确 |
| 真实模型冒烟 | 使用同一工具表完成一次真实往返，记录范围而非宣传准确率 |

### 演进与文章

文章主题：“不用框架，先把一次工具调用接对。”图中只画当前链路；后续六层责任可作定位，但不能把 CLI 输出称为完整 L5/L6 产品交付。

## v0.2 · Skill 与 MCP：不改循环，接入方法和能力

### 为什么现在添加

有了普通 Tool，才能演示方法加载和协议适配都走已有循环，而不是各建一个执行器。v0.2 是第一轮扩展，回应项目对 Skill/MCP 的基础支持要求。

### 增量

不增加核心 Module。增加 Skill Adapter 和 MCP Adapter，各自职责独立。

**Skill 子集**：读取明确配置目录中的 `SKILL.md`；校验 name/description；初始只给模型目录元数据，通过既有 Tool Host 按需读取正文和允许的相对资源。限制资源体积、路径越界和符号链接逃逸。正文保留来源及内容版本，不自动执行 Skill 中的脚本，不把 `allowed-tools` 当授权。

**MCP 子集**：使用实现时锁定的官方 SDK；stdio transport；启动配置、握手、工具发现、分页目录（协议要求时）、结构参数、调用结果、协议/业务错误、超时及关闭。工具名使用确定的服务命名空间以处理冲突。模型看到的工具描述来自同一绑定，不手工改写 Schema 以伪造兼容。

仓库包含一个实际运行的只读 MCP fixture server。它通过子进程标准输入输出完成真实协议往返，不用内存 mock 冒充 MCP 集成。

MCP 工具仍由 K3 Host 授权、校验、派发和记录结果。服务的只读提示是元数据；信任前提是本机用户明确允许启动的服务及其具体能力，不是发现成功即获得权限。

### 不做

远程 OAuth、自动安装任意 npm 包、全网 Skill 扫描、插件市场、MCP prompts/resources 全协议承诺、动态热更新、自动执行远端返回的脚本。

### 验收与演示

同一比较任务分别使用内建读取工具与 MCP 读取工具；循环无需按 MCP 分支修改。模型按需读取 Skill 后采用比较方法，读取过程能在回执中看到。未授予的 MCP 工具不能执行；恶意 Skill 资源路径被拒绝；工具名冲突可诊断；服务断开作为局部失败；CLI 结束后子进程被正确释放。

恢复尚未实现，不能声称冻结版本能跨重启续跑。后续 v0.5 在持久身份出现时再固化这些绑定。

建议示例入口：`npm run demo -- --case skill-mcp`。文章主题：“Skill 提供方法，MCP 提供工具，它们不需要新的 Agent Loop。”

## v0.3 · Plugin 与 Hook：把两种接入收敛成小型扩展面

### 增量与删除

新增 K4 Extension Host。把 v0.2 入口中分别装配 Skill、Tool 的重复代码替换为显式贡献注册，不保留新旧两套装配路径。Hook 执行属于这个扩展机制与 Tool Host 的协作，不另造全局事件总线。

只支持项目内或用户显式信任的本地扩展。一个扩展描述包身份、版本及 Tool/Skill/Hook 贡献；所有贡献先验证再整体接纳，失败不残留半套注册。运行开始时绑定本次使用的扩展集合，下一次运行才使用新版本；不做不停机热升级。

Hook 初始面仅包括调用前、调用后、调用失败及释放。顺序确定、输入只读、超时有界。调用前可按已有策略拒绝或提出有限参数修正，修正后必须再次进行参数与权限校验；调用后不能改写已经记录的真实结果，只能形成标注过的模型视图。观测 Hook 失败不能抹掉已经成立的工具回执。

### 真正的扩展验证

仓库提供文档比较与合成 ETF 两个小扩展包。第二个包至少贡献一项新工具和一份方法，不修改 K1 Runtime。简单领域扩展可在退出后释放注册和资源，原运行记录不被删除。

第三方代码在宿主进程执行意味着具有进程权限。本版不把本地注册、TypeScript 类型或 Hook 超时称为安全沙箱；不接受未经审阅的任意代码包作为安全支持范围。

### 验收

正常注册；重名拒绝；注册中途失败回滚；工具后 Hook 报错仍保留结果；调用前修正后重新校验；下一 Run 使用新版本、已开始 Run 不被替换；资源释放可重复调用且不泄漏 MCP 子进程。扩展删除后不得留下循环中的包名条件分支。

建议示例：`npm run demo -- --case plugin-swap`。文章展示“增加和移除一个领域扩展”的差异，而不只列注册 API。

## v0.4 · Result、RAG 与 Context：研究材料不再等于聊天记录

### 增量与责任

新增 K6 Research Result、K5 Context。RAG 是资料访问扩展，不是第三个事实数据库。

- Research Result 保存来源、内容版本、读取窗口、结果身份、原文与派生关系。采用内存 Adapter 即可，但外部消费者只拿稳定引用和受控读取接口。
- Context 从原请求、已结算回执、方法和当前结果装配下一轮模型输入；明确容量上限与溢出处理，不修改底层事实。
- RAG 先做词法检索：返回候选位置，再由读取工具展开原文。搜索命中不自动等于读过全文。
- Citation 从实际读过的结果窗口发行引用；渲染时可回到对应快照或片段。数字计算结果携带输入引用、方法/代码版本、单位与舍入口径。

移除“每轮把所有工具原始输出塞回 messages”的实现，保留来源回读能力。此时不添加 LLM 摘要压缩；超过容量优先选择需要的结果、分页读取或明确返回不可表达，不能悄悄截断用户问题、工具 Schema 或半个 JSON。

### 时间与金融最小口径

资料版本、取得时间、数据实际截止日分开保存；未知 `dataAsOf` 保持未知。合成 ETF 扩展只计算定义清晰的指标，例如按提供权重聚合行业占比。币种、权重口径、缺失比例、Decimal 舍入均显式。不可用检索文章日期代替真实持仓截止日。

### 验收

命中未读不能发行原文引用；引用能定位准确版本与窗口；旧引用不因后来重新抓取而漂移；无效 ResultRef 被拒绝；派生数字可以用原输入复算；Context 裁剪不改变来源授权；没有证据时正文解释缺口而非补造引用。

建议示例：`npm run demo -- --case grounded-comparison`，以及 `--case synthetic-etf`。文章主题：“从工具输出到可回读结果：为什么 Context 只是工作视图。”

## v0.5 · Session 与 Recovery：进程退出以后仍是同一件事

### 增量

新增 K7 Session & Recovery，使用本地 SQLite。把 v0.4 的内存结果 Adapter 替换为可持久化 Adapter；K6 仍拥有结果语义，不因共享数据库就把结果、授权和运行状态合成一个万能 Recovery 对象。

持久化内容包括原请求、Run 身份、模型配置身份、获准能力快照、扩展版本、资源消耗、封存的模型回合、调用意图、执行回执、结果引用、取消与下一合法动作。凭据不写入 checkpoint；恢复时重新从用户指定的安全配置解析同一配置身份。

工具效果区分至少：尚未派发、已派发待定、成功、失败、unknown。对收到且已提交的回执直接消费；对未知远端结果，只有能力本身提供幂等键或查询对账才能安全收敛。不可把一般 MCP 调用当作恰好一次执行。

本版单个 Run 只有一个有效写入者。SQLite 事务提交 claim/lease/fence 与效果回执；网络调用不得占住数据库长事务。旧 owner 在租约被接管后不能提交晚到效果。租约时间参数是可配置运维值，不是安全正确性的唯一依据。

### 运行合同

建议入口：`npm run start -- inspect --run <id>`、`npm run start -- resume --run <id>`、`npm run start -- cancel --run <id>`。这些入口只从该版本起出现。live Run 的恢复仍要求显式 live 配置；不得自动切换替身来制造完成记录。

原 Run 恢复保留身份、原授权、已消耗预算、截止约束及确定结果。终态后用户新要求属于新 Run，可记录 parentRunId，但不是伪装原任务没有结束。恢复旧代码/协议不匹配的数据时明确拒绝并说明支持范围。

### 故障注入验收

| 注入点 | 预期 |
| --- | --- |
| 模型响应已封存、工具未发出 | 恢复同一提议，不重新让模型选一组动作 |
| 工具结果已提交、下一轮未开始 | 消费原回执，不再执行已结算调用 |
| 工具请求发出、没有确定回执 | 标记 unknown，按工具语义查询或安全停止 |
| 取消已提交、旧工作稍后返回 | 取消不被撤销，晚到结果不能推进 Run |
| 旧 worker 与新 worker 重叠 | 只有持有当前 fence 的提交被接受 |
| 资源已经消耗后重启 | 不重置轮数、不刷新原截止时间 |
| 数据格式版本不支持 | 无破坏地报错，不静默清库或降级 |

### 演进与边界

CLI 可输出已保存的最终结果，但正式 Publication、多版本正文和浏览器交付放在 v0.6。本版的持久事件是恢复事实，不是可以直接公开给用户的 SSE 流。文章展示一次真实的新进程恢复及 unknown 路径，不只展示序列化再反序列化。
