# 01 · v0.1—v0.6：先完成基础研究闭环

> 全部为规划。命令和路径是各版本的实施目标，当前方案仓库不能直接执行。各期按能力依赖推进，当前文件只定义本项目的工程目标。

## 共同交付合同

每期都包含完整代码、自己的fixture、依赖锁、环境说明、默认演示、真实模型配置入口、必要回归与演进说明。拟保持 `npm ci`、`npm run build`、`npm test`、`npm run demo -- --case document-compare`。显式 `--live` 才访问用户配置的模型；模型替身与真实模型共享Loop/Host，不另外编写演示执行引擎。

每期都有相同的短文档比较任务，以及本期新增能力案例。默认脚本网关只证明程序往返；真实模型是否选对材料、保留条件、正确计算单独判断。安装依赖可能联网，“默认离线”指安装后运行不要求外部模型或私有服务。

## v0.1 · 极简但已交付：读资料，保存带出处的报告

**问题**：从用户原话到实际读取和实际文件，先走通一次工作。

### 实现范围

三个核心责任：Runtime推进有限模型/工具循环；Gateway编码一种声明支持的模型协议；Tool Host绑定工具描述、参数检查、执行入口和回执。CLI、来源表和保存函数先是少量普通函数，不预建独立平台。

初始工具：`read_page`读取允许的合成文档；确定性计算接收明确数字/单位；`save_report`将确定的正文和已读来源保存为Markdown。模型负责比较与解释，保存函数不暗中再调用模型润色。

每次Run使用唯一目录，保存 `report.md`、最小manifest和 `run.jsonl`。manifest包含来源名称/版本/物理页或片段、已读原文快照/摘录、文件ID/哈希/媒体类型和保存回执；不是完整Publication账本。保存路径由Host确定，模型不能指定任意宿主路径。采用临时写入及受限发布路径，不覆盖已存在的不同内容。

初始输入保留用户原文，工具参数/返回运行时校验，调用ID匹配，有限轮数/工具数/超时/取消，缺失或未知结果明确表达。模型可直接回答，但要求文件的任务必须有真实保存回执才声称已保存。

### 可观察演示与检查

- 读取A/B相应页，生成差异与共同限制，文件末尾保留两边出处；进程退出后用文件读取检查正文、来源与哈希。
- JSONL能区分模型提议、工具返回、文件保存；它不是可执行的恢复日志。
- 未知工具、非法页码/路径、截断模型调用不得变成有效执行；日志失败和文件失败各自报告。
- 取消后不派发新动作；保存失败不得声称文件可用，已有文本可独立展示。
- 初始固定四题只验证本期支持部分；HTTP下载和复杂语义未覆盖就标not-applicable/unreviewed。

**不做**：数据库、Checkpoint、后台、Plugin、Hook框架、RAG、Memory、Web Chat、任意shell。保存文件及重新打开文件不等于恢复未完成Run。发生中断只保留已有可读产物；重试未知写效果不能用“重新开始”偷偷重做。

**退出条件**：新clone能运行；报告真实可读；来源与取得的原文一致；失败不伪造成功；同一执行链有一次获准的live往返记录。文章主题是“一个最小Agent如何交出第一份可核对的报告”，而不是“我们先建好八个核心”。

## v0.2 · Skill与MCP：方法和外部能力走原工具链

**前置**：v0.1工具描述和执行已绑定。

### 实现范围

Skill从显式配置的本地内容/目录加载，先给模型name/description等目录，再通过普通工具按需读正文和允许资源。只实现明确声明的SKILL.md子集；限制长度、相对路径、realpath和符号链接逃逸。方法与版本关联，不自动执行scripts，不按方法文字授予权限。没有必要先安装Plugin系统。

MCP使用实施时核对并锁定的官方SDK，支持stdio服务启动、连接生命周期、工具发现（含分页）、Schema绑定、调用、业务/协议错误和关闭。连接与初始化时序依锁定协议和SDK验证，不混用不同版本的流程，也不手写一套未经验证的兼容协议。

仓库提供真正运行的只读fixture server。MCP返回文本/结构化数据按声明类型处理，不把不支持的内容块变成“空文档”。模型callId和协议请求身份分别保留映射。服务启动参数来自用户可信配置，不来自资料正文。

### 模型接口补齐

完善所选单一模型协议的JSON/SSE接收：调用参数按ID分缓冲，限制大小，等待协议完整终态后才派发；网络EOF或恰好可解析的半途JSON都不能替代完成标记。usage缺失保留未知。模型响应流与未来面向浏览器的SSE交付是两件事，此期不需要Web UI。

### 演示与检查

同一比较分别使用内建读取和MCP读取，Loop不识别MCP专用分支；模型先读方法再读取资料。检查目录分页不完整、命名冲突、错误参数、服务断连、stdout协议污染、越界资源和进程释放。没有获准的工具不能因发现成功而执行。

**不做**：远程OAuth、自动安装第三方包、完整MCP所有能力、版本热升级、Skill脚本运行。方法内容的本Run快照可以先保留在内存/记录里，跨进程续读的持久合同到v0.7才承担。

**退出条件**：真实子进程协议往返与模型工具往返分别可复现；Skill目录/实际读取/模型采用不混为一个状态。示例目标：`--case skill-mcp`。

## v0.3 · Hook与受限分工：先本地协作，不先做分布式系统

**前置**：读取和返回来源已可核对。

### Hook

普通显式回调数组即可。定义派发前、结果返回后、失败、结束释放的准确位置和字段。顺序固定、输入复制/冻结、执行有时限。前置只改声明字段及精确别名，保留original/effective参数，修正后重做结构/权限检查。后置观测不改原回执，失败不把成功工具变成失败。

特别区分“结果已返回”和“结果已持久化”。回调位置、输入和保证范围必须在实际调用点定义并测试，不能仅凭after等名称假定持久化已完成。

### 两种分工，分别交付

`batch-read`：同进程的受限并行worker，按taskId收集来源和结果，共享根预算。该模式只有固定读取动作，**不能标成独立模型Agent**。

`model-child`：显式启用的一层模型子循环，复用同一Runtime，独立局部上下文、窄工具/材料集合、交接包和取消信号。它是本项目选取的扩展目标；只有真实模型轨迹证明Child独立调用后才宣传此能力。它不要求独立OS进程、数据库、持久等待或后台任务。

两者都由Main综合最终正文，Child不直接公开发布、不扩大授权、不复制完整根预算。子任务失败保留局部缺口；输出摘要标为派生观察，原来源仍可回查。先给子任务足够的原问题/共同维度，不复制全部聊天。

### 观察与检查

此期提供只读元数据时间线/初版observe：按Run/callId关联调用、耗时和返回用量，缺失费用不记零。测试反序完成仍配对、局部失败、最后一份预算不能被多次领取、根取消传播、后置观测故障与资源清理。模型Child另检查独立请求与任务边界，批量读取通过不能替它通过。

**不做**：Plugin热替换、递归代理网络、持久Child恢复、事件游标等待、跨进程调度。进程结束可读取已保存报告，但不能继续尚未完成的子任务。

**退出条件**：Hook和分工各自可移除而默认单Agent案例仍工作；两种示例明确标识。暂未通过的model-child只能留候选，不得用batch-read替它声明完成。

## v0.4 · Context、RAG与引用：让资料可以离开窗口

**新增责任**：K5 Context、K6 Research Result；此前的简单来源数组由其接管，不保留两套来源真值。

Result保存本次实际取得的文档版本、窗口、原文和派生关系，可采用本地文件快照；Context只为下一模型请求投影材料。用户原话、调用配对和必要限制优先保留，不切半个调用组、Schema或JSON。

检索先采用词法：限定资料集合→查询候选→按命中的文档/页码回读→选择上下文→回答。默认固定演示读页与真正候选驱动读取必须有不同案例。改变查询或fixture措辞时，验证返回候选及实际read_page随之变化，不能始终读取写死的位置再声称RAG已生效。

需要容量处理时先外置原文，留下可精确回读的引用。恢复原窗口不重新抓取“最新版”；来源、内容版本和定位保持关联。此期不做模型摘要。计量标明字符/字节或已知token估算，不把本地字符上限当Provider精确窗口。

### 可选检索升级

先验证词法检索能否找到代表性问题需要的原文。出现同义表达召回不足、候选排序不合适或规模问题后，再评估向量、混合检索、RRF和重排。默认示例不依赖外部向量平台；单独的排名融合演示不算接通语义检索，真实接入需单列配置和证据。

### 引用与验收

报告编号映射实际已读来源，比较需要两边出处；关键词命中、目录和模型摘要不得标成已读全文。未知引用可标不可用，不让模型补造。数字引用保留输入、单位、差值/倍数口径及代码身份。

验证旧报告仍指向旧来源、无效引用被拒绝、回读内容与原快照一致、另一侧无命中仍如实说明。拟演示：`--case retrieve-reread`，共同四题继续运行。

## v0.5 · Compaction与Memory：两种不同的后续输入

**前置**：v0.4有真实回读路径。

Compaction先保留reference-only外置，再为完整已结算旧组生成派生工作笔记；用户原文和未结算动作不摘要重写。摘要记录来源区间、调用和结果引用，模型只生成文字，Host关联身份。生成失败、无净节省、基础已过期时放弃摘要，不清空原材料或已保存报告。请求成本计入原根预算。

Memory显式list/search/save/revise/forget，本地文件库即可，单写入者和原子保存；记录条目版本、来源和操作回执。共享给下一任务必须显式指定库位置；临时要求不自动变永久偏好。模型可提出候选，写入需用户明确保存意图和Host准入，不能以“以后”关键词自授权限。

忘记至少分两档：基础行为是不再从当前可用库召回；本项目加强目标是未来投影也排除旧Memory载荷，保留必要操作事实，防止旧摘要重新注入。两档分别验证，不能用存储层删除成功代替模型输入中的排除检查。历史报告或已导出文件不因此被自动擦除。

### 关键界限与验收

存盘摘要/记忆可供新任务读取，不等于原Run可冷恢复；v0.7之前不宣传resume。测试压缩后原文仍可回读、摘要失败回退、净容量计算、保存回执与实际采用分开、同版本更新冲突、forget后未来请求不复活、默认不保存敏感值。模型语义变化选目标题检查，不以长度下降证明质量更高。

拟演示：`--case compact-and-reread`、`--case explicit-memory`。不做多账户共享、自动后台学习或向量记忆平台。

## v0.6 · 报告阅读台与检查工具：基础研究闭环

**范围**：此期提供报告阅读与检查，不是完整聊天产品，不要求后台研究或冷恢复先成立。

将v0.1的小型save_report深化为独立Report/Artifact能力，保留固定内容身份、修订、来源快照、文件清单和读取入口。支持Markdown/HTML/CSV/SVG，格式真实匹配；文件登记失败与已有正文分别处理。只读本机reader按Artifact ID读取，禁止任意路径，HTML/SVG下载或隔离预览，不执行资料脚本。

拟入口：`npm run demo -- --case document-compare`先保存，`npm run serve -- --run <id>`只读取。刷新/重开不调用模型、不重跑研究。更新报告产生新修订，旧链接仍指向原内容；不要求流式预览或SSE多段发布。

`observe`只回查元数据；`evaluate`经真实本机HTTP取回报告、来源窗口和附件，检查身份/格式/字节。语义质量由明确的人工/模型评审单列，默认保留unreviewed。四题保存完整分母；模型调用成功、文件可取和答案正确是不同判断。

### 本期工程练习

可另附一个标准库Python结构化行转CSV的独立练习，明确输入文件和执行命令；它不是Agent可调用执行服务，更不是隔离沙箱。默认报告仍由已有确定性工具生成，不强迫所有读者安装Python。

新增“功能变化表CSV”作为一次能力扩展示例：结构化行→确定性编码→原Artifact登记→报告关联→页面下载。测试逗号、引号、换行与下载字节；必要时处理表格公式注入且说明展示变换。新增生成器后删除旧页面拼接逻辑，旧报告仍可读取。不新增一套Run/来源/发布状态。

### 退出条件

能力覆盖矩阵中的基础研究目标逐项有代码和验收入口，可选项单列实际状态；所有早期标签仍可独立运行。用户能打开报告、原页和附件，四题的可程序检查与待语义复核项有据可查。本机只读服务明确访问边界，不冒称公网安全服务。

责任、局部失败和可替换性通过真实接口与改动体现，不增加额外审批流程。用户可以停留在这个可独立使用的版本；需要持久执行时再升级v0.7。
