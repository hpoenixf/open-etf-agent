# 06 · 成熟度、验证与安全边界

> 本文件是验收设计，不是已执行记录。不以检查数量证明质量，也不要求每次确定性的职责调整都进行模型 A/B。目标是最小充分证据和最后候选的可复现性。

## 1. 什么能力可以进入正式版本

进入候选开发前，明确它解决的实际问题、成熟设计依据和准备保留的行为不变量。不要因为技术亮点、文章缺章或源码已存在，就把一套正在反复重构的机制搬进默认内核。

进入发布版本前，同时满足：

| 维度 | 需要回答的问题 | 不接受的替代证据 |
| --- | --- | --- |
| 行为成熟 | 正常、失败、取消、重复/恢复的承诺是否已明确？ | 原仓库有同名模块 |
| 职责成熟 | 谁拥有事实和局部拒绝？能否保持升级局部性？ | 测试很多、代码行数很少 |
| 独立可运行 | 新 clone 的当前标签是否具备全部必需内容？ | 作者电脑能运行、依赖私人目录 |
| 新实现正确 | 本版本接口与故障场景是否真实验证？ | 直接继承 Lab 或其他项目通过记录 |
| 公开安全 | 数据、源码、依赖许可、凭据与执行能力是否可公开？ | 新 Git 仓库就天然没有泄漏 |

这些内容写入该期的 scope/verification 文档，不另建复杂的审批系统或评分平台。暂不成立的能力继续在 Lab/研发环境收敛；公开候选 PR 可说明未验收，但不能列入已发布稳定能力。

## 2. 四类验证，不混成一个通过数字

### A. 代码与契约检查

类型、Schema、授权集合、幂等键、状态迁移、局部失败、依赖方向和数据迁移。对确定性的责任收敛，推理加针对性契约测试通常足够；无需为了删除重复 Owner 去做大规模模型 A/B。

### B. 真实本地机制

子进程 MCP、真实 SQLite、新进程恢复、HTTP/SSE、浏览器刷新、后台进程、真实 PDF 文件和容器执行。可以使用合成数据和模型替身，但不能用进程内 mock 替代本项要求的物理机制。

### C. 模型语义检查

Prompt、Skill、上下文选择/压缩、Child 委派策略等存在语义不确定性的修改，采用小规模目标任务与必要对照。记录模型、输入、配置、候选 SHA、失败与成本。模板更长或工具调用更多不自动算改进。

### D. 用户交付检查

从公开入口提交任务，再从用户可用的 History、引用和下载端点读取结果。读取服务端内部对象不代替用户实际能获得结果。文件存在、下载字节正确、正文内容正确分别核对。

## 3. 累计关键场景

下面是行为类别，不是要机械新增固定数量的测试文件。已有测试覆盖同一合同可复用；只对变化和高风险交接追加证据。

| ID | 首次要求 | 场景 | 核心断言 |
| --- | --- | --- | --- |
| C01 | v0.1 | 普通 Direct 与 Tool Loop | 一套 Runtime；真实调用 ID 与结果对应 |
| C02 | v0.1 | 未知工具、无效参数、截断响应 | 未通过准入的动作未发生执行 |
| C03 | v0.1 | 超时、资源耗尽、取消 | 有界结束；不通过重试得到无限额度 |
| C04 | v0.2 | Skill 路径与 MCP 断连 | 越界读取被拒绝；协议失败保持局部；关闭资源 |
| C05 | v0.3 | 插件注册中断与 Hook 错误 | 无半注册；后置回调不能改写真实效果 |
| C06 | v0.4 | 候选、原文、摘要、引用 | 未读原文不冒称已读；旧引用不漂移 |
| C07 | v0.5 | 原模型回合/工具回执后崩溃 | 新进程消费原记录；不重复已结算动作 |
| C08 | v0.5 | 已派发但无确定回执 | unknown 不被解释为失败未执行；不盲目重放 |
| C09 | v0.5 | lease 接管、取消与晚到提交 | 旧 fence 失效；取消不被复活；预算不重置 |
| C10 | v0.6 | 发布提交、SSE 断线、浏览器刷新 | 同一修订可回读；不重发成重复消息；预览不冒称已保存 |
| C11 | v0.6 | 附件失败和恶意显示内容 | 已有独立正文保留；下载受限；页面不执行资料脚本 |
| C12 | v0.7 | Child 成功/失败/中断 | 独立模型执行、根预算、真实交接、不重复委派 |
| C13 | v0.7 | 后台 A 与短问 B | 客户端关闭不取消 A；结果按 Run 分别归属 |
| C14 | v0.8 | 压缩失败与记忆忘记 | 原材料可回读；失败可回退；忘记后不被旧投影重注入 |
| C15 | v0.9 | 网络、PDF 与隔离计算限制 | 越界被拒绝；读取缺口明确；计算输入和产物可核对 |
| C16 | v1.0 | 外部开发者复现与换扩展 | 只用公开仓库/接口运行；无私有路径依赖 |

对恢复和并发，组合交接比单模块 happy path 更重要。至少包含“Child 完成→Root 中断→恢复→正文提交”和“正文提交→客户端断线→History重放”，而不是只测各自序列化。

## 4. 每期检查的合理规模

每期运行当前候选的离线默认 demo、受影响契约检查和累计关键交接回归。模型协议改动用一个目标真实往返检查；方法/上下文语义改动用能揭示差异的任务。不要每个文档或命名改动都重跑全部付费任务。

发布前的完整回归针对最终 SHA；修复后保留失败记录及被修复位置，不把旧失败当当前故障，也不把多个候选的成功拼成一份完整通过。

确定性 demo 使用固定 fixture/时钟输入或明确的可忽略随机 ID；真正模拟错误注入点，不靠运行日志中打印一句“recovered”验收恢复。对进程间行为使用实际新进程；对长时间策略可用受控时钟减少无价值等待。

## 5. v1.0 的真实模型复核

建议两模型 × 四至八任务作为有限候选校验，不是统计意义的准确率估计。任务包括：明确功能差异、带条件限制的结论、确定性数值比较、有来源的综合报告；按已支持的 Child、压缩及资料工具增加目标场景。

每条记录保留任务/fixture 版本、模型配置标识、实际输入范围、Run 结果、正文修订、附件检查、错误与用量缺口。对内容分别评估任务遵循、来源支持、计算正确性、限制说明，不能用一次 LLM judge 代替作者签审。

人工未复核就写 `unreviewed`，工具结果未知就写 `unknown`，交付不完整就写 `partial`。发布声称已经验证的固定用例须完成所需复核；失败用例不能删掉后只展示漂亮结果。

真实调用必须获得使用对应服务及成本范围的授权；本方案不授权新开账户、充值、上传私人数据或无限重试。无需为了 v1.0 资格购买新的平台。

## 6. 安全面随版本逐步扩展

| 引入阶段 | 风险 | 最低约束 |
| --- | --- | --- |
| v0.1 | 工具越权、无界循环、配置泄漏 | 服务端能力集合、Schema、预算、取消、错误不含密钥 |
| v0.2 | Skill 文件逃逸、恶意 MCP 服务 | 资源 realpath/范围/大小检查；仅显式信任的服务；固定启动参数；不把返回文本当命令 |
| v0.3 | 插件代码获得进程权限 | 可信本地包、声明权限事实；不伪装沙箱；注册回滚和资源释放 |
| v0.4 | 资料提示词注入、引用伪造 | 原文身份与指令身份区分；引用由 Host 从真实读取发行；结果不直接升格为系统消息 |
| v0.5 | 状态篡改、重复效果、隐式扩权 | 事务、schema版本、fence、原grant、unknown；凭据不入持久状态 |
| v0.6 | 未授权本地 HTTP、XSS、文件路径攻击 | loopback＋会话令牌＋来源/写请求防护；安全 Markdown；隔离 HTML/SVG；只按 Artifact ID 读取 |
| v0.7 | 僵尸 worker、Child 扩权、预算裂变 | 根取消传播、租约/fence、工具子集、共享资源计数、晚到提交拒绝 |
| v0.8 | 摘要丢事实、记忆泄漏或复活 | 来源谱系、显式写入、撤回标记、后续投影排除、保留政策 |
| v0.9 | SSRF、解析器、任意代码执行 | 逐跳网络策略、解析限制、无宿主密钥、受限容器、禁网与资源限制 |

安全措施是限制已声明效果，不为无关失败增加全局正文否决。观察 Hook、日志平台或评估器不获得新的执行/发布权限。

## 7. 隐私与许可

只提交自行编写或有明确再分发权的源码、方法与 fixture。不能复制公司代码、私有提示词、生产记录、真实客户资料或私人书稿全文。使用公开文章只链接并提炼设计，不复制不可公开的截图、图源或原工具载荷。

新仓库也需要扫描完整待提交文件及历史；测试数据、截图、SVG元数据、样例配置、日志、lockfile来源都需检查。密钥放 `.env.example` 占位说明，真实 `.env` 与运行目录必须忽略。发现凭据时删除文件不足以解决风险，应按实际泄漏范围处理并轮换。

许可证建议使用一种简明、与目标依赖兼容的宽松许可证，具体选择由项目所有者确认；本方案不擅自把既有书稿和私有代码一起重新授权。正式发布前补齐 LICENSE、第三方说明和数据出处；许可未确认不能宣传已提供相应开源授权。

## 8. 状态表达与停止条件

发布状态使用 planned、in-progress、candidate、released；能力资格单独记录 engineering/local-integration/live-reviewed 等证据范围。状态名称不是新的数据库业务模块。

遇到以下问题应停止扩大本期范围：公共接口仍反复穿透其他模块；必须依赖私人服务才能演示；恢复会盲目重放未知效果；安全 profile 只剩 mock；文章说完成但公开入口无法跑通；模型语义评估没有覆盖实际修改。此时修复或缩小范围，不新增一个监督所有模块的 Manager。

## 9. 本次方案 PR 应执行什么

只检查文档本身：版本/分支名称一致、核心数增量一致、26章无遗漏、Markdown链接与围栏、公开数据边界、未来命令有规划标注。可以检查 git diff 与文件清单；不能报告本项目的 Runtime、MCP、恢复、浏览器或真实模型已经通过测试，因为本 PR 尚未实现这些能力。
