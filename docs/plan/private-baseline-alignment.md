# Fixed-baseline capability alignment / 固定基线能力对齐

This is the single capability inventory for the [English roadmap](v1-to-v2.md) and [中文路线图](v1-to-v2.zh-CN.md). It is a planning/evidence map, not a second execution owner or a claim that private implementation is public. 本表是唯一对齐清单，不另建执行 Owner，也不将私有实现描述为公开交付。

## Frozen scope / 固定范围

- Private reference / 私有参照: 2026-10-28, `4bd07ab3a4df41d8f647ea1599aa5ab41ed26c0e`; 47 canonical responsibilities. Later private-main changes do not silently expand this target. / 47 项标准职责，之后 private main 变化不静默扩大目标。
- Public baseline / 公开基线: v0.10 at `c9a6d28954a77a48a1cf1cfce32d404d800ba2c5`; fixed executable qualification is narrower than all documentation on that commit. / 文档所在提交不扩大原执行资格。
- Module definitions are not stability certificates. Engineering checks, real-model behavior, semantic usefulness and cloud qualification remain distinct. / 模块定义不等于稳定性；工程、真实模型、语义效用和云部署分列。
- Only safe capability abstractions and scope summaries are public here. Private source paths, raw logs, credentials, holdings and internal audit links are excluded. / 仅公开安全能力抽象与范围摘要，私有路径、原始日志、凭据、持仓及内部审计链接不公开。
- E04 means research-call evidence retention/readback, not a duplicate billing owner. / E04 为研究调用证据留存/回读，不是新增费用 Owner。

## Stability-led migration waves / 按稳定度推进的迁移批次

Waves are ordering buckets, not version numbers or bundled releases. Each selected increment requires one module's independent Spec, implementation, counterexamples, real consumer and affected local/cloud checks. Preserve v0.11 PDF and already approved ordering. / 批次是排序容器，不是版本号或打包发布；每个增量独立完成一个模块的 Spec、实现、反例、真实消费者及受影响本地/云检查，保留 v0.11 和已批顺序。

- **M0, through Nov 11:** only the qualified slices needed by G01–G12; no entire-owner parity implied. / 到11月11日，仅首个云 MVP 所需切片，不暗示整项 Owner 对齐。
- **M1, planning window Nov 12–Dec 9 (weeks 3–6), after cloud go:** independently stable research/evidence and interaction gaps with existing consumers. Scope the next one or two versions after actual cloud feedback. / 云端通过后规划11月12日–12月9日（第3–6周）首批，优先稳定且有消费者的研究证据/交互缺口，依据反馈界定下一至两个版本。
- **M2, planning window Dec 10–Jan 20 (weeks 7–12), after dependencies qualify:** context, recall, specialist and data-domain extensions in the existing candidate sequence. / 规划12月10日–1月20日（第7–12周），前置通过后按原候选顺序推进上下文、召回、专业协作及数据领域扩展。
- **M3, Jan 21 onward, re-estimated at each accepted batch:** scheduling, cross-process coordination, richer private operations and any reference modules whose private evidence is partial/WIP. No delivery date is invented; resolve original stability gaps before copying behavior. / 1月21日之后逐批重估，远期门槛包括定时、跨进程协调、更丰富私有运维及参照仍部分/WIP的模块，不虚构日期，先处理原稳定性缺口再迁行为。

These windows reserve review/iteration capacity, not completion of every row assigned to the wave. Missing prerequisites move dependent work; each accepted module triggers re-estimation, and no fixed all-47 completion date is claimed. / 这些窗口安排审查与迭代容量，不保证完成该批全部行；前置缺失则顺延依赖工作，每个模块验收后重估，不承诺47项全部完成的固定日期。

Every wave continues until the selected fixed-baseline responsibility is either independently qualified in Open or explicitly recorded as an unresolved gap requiring a later increment. “Deferred” is not “aligned”; the target is not silently reduced. / 每批持续推进，固定基线职责要么在Open独立合格，要么明确保留后续缺口；延期不等于已对齐，不静默缩减目标。

## Updating this matrix / 更新规则

An accepted increment records the exact public source, real consumer, scoped tests/readback and local/cloud applicability; refresh only the affected rows, retaining historical failures and narrower evidence. The fixed private reference changes only by an explicit new baseline decision, not a background sync. A later cloud deployment does not turn every row's cloud U into passed. / 每个通过增量记录固定公开源码、真实消费者、有界测试回读及本地/云适用性，只更新受影响行，保留历史失败和窄证据。固定私有参照仅经显式新基线决定改变，不随后台同步漂移。以后部署成功也不能把所有行的云U改为通过。

Full alignment requires a reviewed outcome/contract comparison for every one of the 47 rows. It does not require importing private source, databases or accounts, enabling every capability at once, or proving investment profit. Blocked or intentionally disabled capabilities remain visible gaps until independently qualified; financial usefulness is assessed separately using authorized cases. / 全面对齐要求47行逐项经过结果/契约对照，不要求导入私有源码、数据库或账号，不要求同时开启所有能力，也不等于投资盈利证明。阻塞或主动关闭的能力保持可见缺口，直至独立合格；金融实用性以获准案例另评。
