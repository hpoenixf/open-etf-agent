# Run 控制与终结归属

本 v0.20 候选将 **Runtime 的决策** 收敛到 `src/run-control.mjs`，不迁移授权。原 Session 的 `claim.finish` 仍是带 fence 的持久终态写入者。取消、RootBudget 预约、grant、Child 身份及 Gateway/Admission 未知结果仍由原 owner 管理。决策函数不执行工具、不发授权、不退款、不释放票、不重开终态 Run。

## 事实和决策

- 工具成功后继续原始配对历史。只有原 Host 能复验精确调用身份、JSON 持久化一致的纯校验证据，且是无 hooks、无部分效果、无未知效果的单调用组，才允许一次纠错。纠错沿用原 Run 和模型预算；第二次拒绝以 `CORRECTION_LIMIT` 停止。
- 保留原计算校验证明。新增报告证明仅涵盖参数字段、非空有界正文、sourceIds 集合结构和附件集合结构，**不证明来源存在、编号引用正确、文件可读或已获授权**。未取得下方有界引用纠错所述原Result证明的有状态错误继续拒绝；单凭这里的纯结构证明不能授予状态性纠错。真实已获取的 sourceId 即使长得像 ResultRef，也由原 Result owner 的身份决定，不能按字符串形状否决。
- 已封存的模型 final 只有满足原报告要求且没有未结算结果才能收尾。这不是新增仅输出模型阶段，也不会把 final 文本冒充已保存报告。
- Publication 已提交后，普通 `onPublication` 通知异常不能撤销精确原正文。已封存 final 实际提交且不会再派发模型或工具后，通知仅获得独立 100 ms 观察窗口；异步未返回只表示未确认，不代表远端已停止。该窗口要求 Node 事件循环仍可响应；可信回调若同步阻塞事件循环，定时器无法抢占。回调不是任意代码沙箱，本次不提供或宣称进程隔离。Runtime 复核实际取消、原 fence 和原回执，再记录 `PUBLICATION_NOTIFICATION_UNCONFIRMED`，不宣称通知已送达。真实取消、身份损坏或失去所有权仍须停止。
- 清理、读回失败不能覆盖已有取消或主失败。必要结果完整性缺失仍阻止成功。release 观察器及最终日志失败只保留未确认事实，不赋予其抹掉已提交结果的权限。旧 `run_finished` 日志增加 `pre-settlement` 标记；最终以 Session 实际终态为准，不把此前日志当原子提交。
- 对 `throw null/undefined` 及抛错的 `code` getter 安全分类，不丢失原预约和 unknown。1–200 字符且无控制字符的字符串 code 保留为诊断，其他值映射为 `EXECUTION_FAILED`。外部抛出 `CANCELLED` 字符串不等于用户取消，须核验原 abort 信号或原 Session 状态。

## 持久化和兼容

`controlObservations` 是可选、有界的检查点增量字段，限定 owner/code 配对并绑定实际 Run ID；旧检查点可不含该字段。最终 outcome 与检查点中的观察必须一致。旧终态失败不会因升级重新执行。新的报告校验证明只能由能理解该契约的 Host 校验，不让旧实现默默误读。

保留原截止契约：截止后不新派发，但原 fenced Session 写入者仍可结算此前已确定的合法终态。异步 release 期间仍观察用户取消。Host stop 是中断，不是用户取消。清理完成或进程消失均不等于远端结算，不释放未知模型/工具效果及其 Admission 占位。

## 尚未改变的边界

未删除 Child 单调用限制，未开放任意插件重试，未推断通用插件计算引用，未重放未知请求。报告来源/编号纠错需要原 Result owner 在当时的精确状态契约，不能从最终集合猜测。Publication 通知与 `onClaim`、`onCheckpoint` 控制/测试钩子不同，后两者没有被统一吞错。新增 `publication-committed` 控制检查点让真实进程硬杀验证独立于通知等待。公开 durable 集成使用原 Session 契约（包括纯检查点预检），不兼容的 store 在创建 Run 或模型派发前拒绝。

v0.20 原四十个真实场景仍绑定实际执行版本，保留失败与 C07 摘要未知。新实现、离线回归、单列付费修复重验和最终发布资格分别陈述，不互相替代。

## 有界的引用纠错与 Child 混批拒绝

已注册的 ResultRef 不等于原始 sourceId。只有原 Result owner 能证明模型把已获取的类型引用误作原始来源，或编号引用超出当时已获取的计算/来源序列时，才提供一次纠正机会。即使 sourceId 外形像 ResultRef，也先按真实原始来源身份处理。任意未知 ID、权限失败、记录损坏和不明副作用不获得此许可。

证明保留原封存提案时完整、有界、有序的 Result 索引。原 Session writer 在首次 result-committed 事务内绑定该基础、Run、grant、call 和未变化的 Host。恢复核验历史基础及原记录，后续新增资料不会改写旧判定。私有索引基础不进入模型工作消息，包括自定义 Gateway。这沿用原本可信本地 Session 存储模型，不声称抵抗任意数据库重写。Hooks、保护档案、部分副作用和未知副作用仍不适用此纠错路径。

包含原串行 Child 的混合调用组，在任何成员执行前由 Child owner 核实原绑定并拒绝。原 Session 单事务按原顺序写齐每条未派发结果，保持调用与结果完整配对。Runtime 可消耗一次纠错机会，让模型改为单独调用。被拒组不扣工具或 Child 派发预算，但此前模型请求仍占原预算；重复错误仍受原纠错次数限制。未知工具、专属响应控制、历史已开始的混批、取消、期限、fence 与预算限制均保留。拒绝不算工作成功，Child 也没有独立发布权。

## 摘要观察期限

新研究项目及明确的配置修订，未指定时持久保存60秒摘要观察期，可配置上限为120秒。既有项目/任务保留原已存值；历史未保存摘要配置的项目继续使用原应用10秒默认值。底层 compaction API 的历史默认值不变。只支持30秒的旧 reader 会拒绝新的更长期限定义，不会静默改变语义。

观察期不会延长原 Run deadline，不增加模型/摘要次数，也不能绕过取消或 provider HTTP 时限。已派发摘要超时后仍是 unknown 并保留占位；停止本地等待不代表远端已取消，也不授权重放。60秒是实用的有界配置，不是对所有 provider 延迟的保证。
