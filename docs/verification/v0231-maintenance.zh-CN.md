# v0.23.1：Runtime 收尾维护

Knowledge 仍是唯一主要模块。此维护增量只修复支撑 Runtime 的两条生命周期路径，不改变 Knowledge 检索、来源身份、模型指导、工具 schema、权限或请求预算。

1. 异步清理及最终落盘期间保留原 Session 心跳。原 writer、fence 和 lease 到期仍是权威边界，不移动原 Run deadline，也不允许清理阶段启动新的模型或工具工作。
2. Run 在等待回答的释放阶段被取消时，返回持久化的取消状态。claim release 无操作时不再把已取消的问题显示为等待中；正常问题身份、期限及回答的一次性采用保持不变。

普通 Child 测试 lease 改为 5000 ms，专门的到期测试仍保留 150 ms。冷进程测试仍杀死独立进程，读取最终持久化的 Main/Child lease，并等待实际到期。改变的是测试时序，不是产品默认值或恢复权限。

## 原完整十题与单独验证的维护变化

[既有 Runtime 范围发布决定](v023-runtime-release-decision.safe.json) 继续绑定原实现和原执行身份。原十题机械 **9/10**、观察到的 Runtime 合同 **10/10**、严格完整任务质量 **5/10** 保持不变，早先 8/10 也保留。不替换原题、失败、源码身份或分数。

[验证合同](../live-validation.md) 允许在执行输入与受影响合同仍适用时继承证据。独审比较了全部 80 个生产文件：其中 79 个与原十题实现逐字相同，只有 Runtime 改变。这是**维护适用性论证**，不是全源码字节等价。原 execution-input 清单仍只描述旧执行，不能用来宣称新 Runtime 与旧实现逐字相同。

两处生命周期变化由当前七项产品回归、两批独审、Child 冷恢复和当前全套另行覆盖。包括另一 Session 连接取消、过期或被新 fence 接管的 writer、原 deadline、未知模型结果、known/unknown host stop、清理/读取异常及心跳停止。旧 K10 检查的是 host-stop 后继续，不是等待回答分支；该分支由单独取消回归覆盖。

固定实现 [a9223e57](https://github.com/hpoenixf/open-etf-agent/tree/a9223e57b676f0bf0180769a348286d75c5ff647) 通过 **966/966 项离线测试**、原生 ESM 构建及[固定提交 CI](https://github.com/hpoenixf/open-etf-agent/actions/runs/42151778991)，包含锁定依赖安装。实际测试 Node **26.11.1**，声明范围仍为 **>=26.8.1 <27**。两批生命周期独审分别 12/12、13/13，其中产品回归有重叠；第一批有意保留当时尚未修复的取消返回观察，第二批验证其修复。不能把这些数字相加，也不能当成新真实批次。

上述证据已闭合受影响的维护合同，无需再发一批模型请求。这不证明任意清理延迟或并发模式都安全；后续行为变化仍需重新分析影响范围。

## 后续不完整观察仍明确保留

新固定源另有两批真实提供方观察：

- 原十题观察完成 K01，在 K02 HTTP 429 时停止：实际请求 4 次，完整 Go 零费用响应 3 份，unknown 1 次，八题未运行。K01 的已观察 Runtime 合同通过，严格内容未通过。
- 单独冻结的 K03–K10 补充完成 K03–K07，在 K08 HTTP 429 时停止：实际请求 20 次，完整 Go 零费用响应 19 份，unknown 1 次，K09/K10 未运行。观察到五题 Runtime 合同，严格内容四题通过；保留 K03 证据叙述矛盾和 K05 措辞风险。

两批都不构成新完整十题资格，不池化、不替换原题、不填入旧分子。被提供方阻断的题没有可用模型答案，不自动归为 Runtime 或模型失败。具体 429 原因和远端效果仍未知，不退回或重放未知请求。原始请求、响应、数据库及私人账户记录不公开。
