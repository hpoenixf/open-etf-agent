# v0.24 provider capacity: fixed-source evidence and limits

**Candidate evidence, not a published release.** The fixed ten-task cohort and independent reviews are complete. Final release-package validation, exact-commit CI, tag and Release remain pending.

Provider Admission is the single main module. In a new-format project, changing the model or streaming configuration for the same normalized endpoint retains the original project-local capacity owner. Runtime and Session continue owning grants, budgets and original Run identity. No new router, billing owner or account-wide limiter is introduced.

## Results and retained content flaws

All frozen tasks **C01–C10 completed**, each with its original persisted Report and Publication:

- **Frozen mechanical result: 10/10.** The original denominator, tasks, rubric and threshold were unchanged.
- **Named Runtime contracts observed: 10/10.** Independent review found no confirmed violation in the reviewed identity, source-consumption, original-ticket, delivery, deadline and cold/HTTP readback checks. This does not establish that all product behavior is defect-free.
- **30 actual requests; 30 complete original Go-zero response bodies with matching adoption evidence; no new unknown request outcome.** Requests and logical tasks remain separate counts.

These results are not a semantic-perfect 10/10. **C09's saved Report still contains a citation error:** its import quotation about 1200 accepted rows initially points to `[1]`, the export source, rather than `[2]`, the import source. Both originals were acquired, and their identity and byte chains are correct. The final Publication explicitly discloses the mistake, but no corrected Report was saved. Disclosure does not repair the original Artifact. Host validates admitted source identity, not sentence-level semantic support; this content error is not a demonstrated Runtime contract violation.

Other retained issues include loose offline-support wording (C01/C02), overstated wording about an unexplained discrepancy (C04), an incorrect source line count (C05), an overbroad “only textual difference” statement (C06), and claims stronger than the supplied evidence about a completion date or present CSV availability (C07/C10). Several reports are unnecessarily long. No separate numerical semantic-quality score is asserted.

## Capacity and compatibility boundaries

The real-provider cohort exercises **serial protocol execution across project revisions**. It does not demonstrate concurrent live-provider contention. Separate provider-free tests cover actual process contention, queued cancellation, retained unknown occupancy, cold readback and compatibility using synthetic transport.

Capacity is one project and one normalized endpoint, with one local slot. Different projects/endpoints remain independent. There is no account-wide or distributed guarantee, automatic unknown reclamation, refund or retry. Missing original capacity state fails closed. Legacy projects retain their original format and ticket paths; gateway changes are refused rather than silently migrated.
