# v0.49.0: Research runtime reliability

The fixed implementation baseline is [a506cf7c74649ce2ba7a167ace65f344de1bdcc8](https://github.com/hpoenixf/open-etf-agent/tree/a506cf7c74649ce2ba7a167ace65f344de1bdcc8). The release increment concerns the **research Runtime**. Deep work can retain a run-scoped working brief ([#29](https://github.com/hpoenixf/open-etf-agent/pull/29)); it is not evidence, a publication gate or extra permission. Standard and previously admitted runs keep their profile semantics.

A locally rejected public-read URL can continue only when the actual selected validator proves there was no dispatched request ([#33](https://github.com/hpoenixf/open-etf-agent/pull/33)). A settled timeout of an optional public web acquisition may be represented as unavailable ([#34](https://github.com/hpoenixf/open-etf-agent/pull/34)); an unknown or cancelled dispatch is not reclassified. The HTTPS and network policy is unchanged: discovery may identify HTTP links without authorizing a fetch, and the app does not guess an HTTPS replacement. The owner workbench can export bounded opt-in telemetry ([#32](https://github.com/hpoenixf/open-etf-agent/pull/32)), off by default; an export problem cannot retract a saved answer or trigger another research request.

[The fixed input source passed the hosted full Runtime job](https://github.com/hpoenixf/open-etf-agent/actions/runs/45374203719). The behavioral checks distinguish prior material, final text, committed answer and exact history readback. They do not certify a market conclusion or live provider reliability. New real-model or Langfuse ingestion qualification is not claimed. There are no new UI assets in the behavioral increment.

The release excludes the draft guest service and draft tool accounting policy.

## 简体中文

本版固定实现对应上面的 commit，主模块为研究运行时。深度研究可留存本轮工作需求，便于重新打开未解决的判断；需求不是证据、授权或发布门。旧工作与 Standard 的语义不变。

工具控制只在证明请求根本没有发出时才允许已知的本地 URL 拒绝继续；原网页执行方确定已经结算的可选超时可明示不可用，取消或结果未知不能误判为已结算。原 HTTPS 和网络边界不放宽，发现 HTTP 链接不代表可以读取，也不猜测 HTTPS 替代。Owner 的元数据观测默认关闭，不是研究的完成条件。

已通过固定代码的 GitHub 完整 Runtime 检查；原资料、本轮生成、正文提交和可回读分别验证。未声明新增模型真实合格、行情语义正确、远端观测接收或新 UI 布局验收。游客服务和工具总量策略保持草稿。
