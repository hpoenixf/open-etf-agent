# v0.22 bounded Child execution: qualification and limits

The release preserves the tested source for bounded, serial, one-level read-only Child execution. Main chooses from admitted methods and narrow source subsets; the original Runtime, Session, grant, deadline and budget continue to own execution. The built-in claim-comparison method now preserves conditions and modality before calling two claims contradictory. Child input and CSV type-only correction use the existing single correction allowance.

## Read the ten-task result literally

The user accepted **same-source, prospectively approved staged validation: nine original mechanical successes out of ten**, with the original C06 measurement failure retained and independent successful supplementary evidence. This is not one continuous 10/10 pass. [Original outcome summary](v022-real-ten.safe.json) and [execution equivalence manifest](v022-execution-inputs.safe.json) bind the fixed evidence.

- Stage two: only C07–C10 were executed, on identical source, fixture and original task definitions. All four passed. The original stage-one state is unchanged.
- 81 new physical model requests have original Go zero-charge guard receipts and completed original admission tickets, with no new unknown. Historical unknowns remain held, not relabeled as free, failed or recovered. Original complete provider response bodies were not retained for retroactive byte verification.
- Independent original-source and report review supports the core of all ten answers. Non-core wording issues remain in C01, C02, C05 and C10; this is not a perfect semantic score or a financial-research qualification.

## C06 remains a failed original measurement

A legitimate rows CSV and report were delivered. A separate optional source-bound calculation export correctly returned `available:false` / `UNBOUND_CALCULATION`. The measurement reader wrongly treated that unavailable result as an artifact receipt and stopped with `HTTP_CSV_ACK_IDENTITY`.

The corrected measurement adapter preserves the unavailable branch and requires original-owner identity; it does not loosen product binding or ignore arbitrary missing artifacts. Independent readback checked the original report (6,244 bytes), original CSV (424 bytes), exact hashes and actual HTTP delivery, plus all ten applicable Child/mechanism checks. No model was called again. That supplement does not change C06 to an original success.

## Provider-free verification and history

The tested source passed the full single-worker **927/927** suite on Node.js 26.11.1 and the native ESM build. The earlier 925/926 aggregate failure is retained: a hot-journal test fixture could lose its unreachable SQLite connection before the intended SIGKILL. The fixture now keeps the connection alive, and a forced-GC regression verifies the boundary. No production Session behavior was changed for that fixture repair. Earlier stopped cohorts and the prior modal-comparison error remain historical failures, not fresh successes.

The final release package's free checks, exact commit, remote CI and GitHub Release are verified separately. Local execution and public source identity are distinct; the manifest permits byte comparison without publishing private source paths, databases, reports, logs or credentials.

## Scope

Supported compositions include original Main-side Memory, calculation/CSV, explicit task time, managed compaction, bounded Child failure and same-Child safe stop/resume. Child tools remain read-only. Parallel/background execution, nested children, peer messaging, independent Child cancellation, Response+Child, Schedule+Child, PDF+Child and trusted-plugin+Child remain unsupported. Unknown dispatched work is never automatically replayed.
