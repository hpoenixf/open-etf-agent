# v0.37.0 · Main context compaction admission (A28)

In an opted-in Project, Main first tries reversible projection, then measures the complete request serialized by Gateway. `compaction.pressureMode: "encoded-request@1"` measures UTF-8 bytes, not tokens or the model's native context window. Existing tasks keep their frozen policy; omitted settings retain the legacy policy. Gateway's hard request guard remains in effect.

Main can reuse a verified working note, but does not repeatedly summarize the same eligible evidence under the same capacity basis when the candidate cannot shrink the complete request. Failure and an uncertain provider outcome are not evidence of no gain. The last root model slot remains available for Main's deliverable. Original questions, the latest complete tool group, authorized exact-source reread, and the v0.36.1 typed Project Memory exclusion remain in scope.

## Qualification

- **10/10** on one prospective, fixed real-provider cohort using authored synthetic materials and DeepSeek v4.1 Flash through OpenCode Go. Admission began separately just before each case; no tasks were replaced, pooled with earlier cohorts, or replayed. A fresh process reopened all ten reports and matched their persisted hashes, original-source references, and completed model reservations.
- **Mechanism.** All five low-pressure cases had under-threshold evidence and did not generate a summary. All five high-pressure cases adopted a working note and sent a smaller subsequent complete Main request. Every case preserved the two expected source references. These are specific Runtime and delivery checks, not a causal model-quality comparison.
- **Provider accounting.** All 60 actual model dispatches reconciled to completed reservations and provider evidence of Go inclusion with zero additional charge. There were no unknown outcomes in the qualifying cohort.
- **Earlier observations kept separate.** The initial planned ten retained 7 successes, 1 unknown transport outcome, and 2 not run. A subsequent launch stopped before any physical dispatch because its guard failed; its ambiguous native reservation remains excluded and conservatively held. Another outright stopped after one response with unconfirmed inclusion/charge. Those outcomes were neither reused nor cleared by this qualification.
- **Provider-free.** The exact behavioral source on Node 26.11.1 passed 1,569 tests, with 4 historical fixed-binary cases skipped and 0 failures. Focused boundary controls covered frozen policy identity, the hard guard, typed Project Memory, no-gain behavior, final model capacity, exact source reread and cold report delivery. Build, module documentation and [Verify](https://github.com/hpoenixf/open-etf-agent/actions/runs/44664348321) passed on the behavioral head. Package and presentation-only changes do not change the qualified Runtime bytes.
