# v0.23 admitted Knowledge: Runtime evidence and model limits

Knowledge is this version's single main module. It connects explicitly imported text to bounded lexical retrieval, returns whole original pages and carries their original Source/ResultRef identity through the existing Report, Publication and Reader. Runtime, Session, source import, Context, Child and the existing permission/budget owners remain supporting components, not new independent modules.

## Read the three results separately

All ten original tasks in the repaired fixed-source cohort completed. Independent review reports:

- **Observed Runtime contracts: 10/10**, with no confirmed applicable implementation defect in the reviewed checks. These checks cover admitted identity and source scope, actual model consumption of original evidence, persisted Report/Publication, cold and HTTP readback, bounded composition, and same-Run continuation. This is a bounded observation, not proof that the implementation has no other bugs.
- **Frozen mechanical result: 9/10.** K10 remains a failed original mechanical check because the model selected a query different from the requested literal value. Its same-Run continuation and terminal checks passed. The Runtime accepts bounded query strings; it does not enforce a natural-language query as a const/enum.
- **Strict complete natural-task quality: 5/10.** K01 has a material contradiction about an explicit internet requirement. K05, K08, K09 and K10 rewrite requested query values. These model choices are not confirmed Runtime implementation failures. All ten contain the core requested facts, but minor language, attribution and unnecessary-inference flaws remain. This is not ten perfect answers or a general model-quality qualification.

The original frozen plan included semantic review as a gate, and its strict complete-task threshold was **not met**. The [dated Runtime-scoped decision (2026-11-06)](v023-runtime-release-decision.safe.json) retains the original nine-success mechanical numerator and limits the publication basis to observed Runtime mechanisms. Model-only defects remain outside the implementation-failure count. This later scope clarification does not rewrite the plan, erase K10 or claim that the strict task gate passed. Independent review verified the receipt-derived declaration; final-package verification and publication remain separate.

## Scope and upgrade boundary

The fixed cohort includes source-snapshot binding, no-evidence/partial retrieval, calculation/CSV, explicitly read-only Memory, serial read-only Child, and safe pause/resume of the original Run. Search scores remain ranking hints. Main-side Knowledge does not add Knowledge tools to Child. Knowledge + Schedule is refused; PDF keeps its separate reader and is not silently indexed.

This version has no vector service, embeddings, reranker, watched directory, live external ACL, multi-tenant collection or automatic reindexing. It does not establish production retrieval quality, financial semantics, browser acceptance or broader concurrency.

The guidance repair changes Knowledge task questions and Host tool-definition hashes. Previously admitted Knowledge tasks must continue on their original fixed executable source; mismatches fail closed, with no transparent migration. Ordinary non-Knowledge guidance is unchanged. Unknown dispatched work is not automatically replayed.
