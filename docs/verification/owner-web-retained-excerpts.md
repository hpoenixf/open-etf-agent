# Public web reading: continuing a retained excerpt

In a new ordinary owner chat turn without a selected or attached source (including no PDF attachment), with public web reading enabled, `public_web_read` acquires one public HTTPS document under the existing network policy and returns the first extracted excerpt. When the result includes a non-null `nextCursor`, the model may call `public_web_continue` with that cursor if the next excerpt would help answer the question. A returned null means there are no more retained excerpts.

The continuation loads the original Run's verified local acquisition and extraction manifest. It does not contact the original URL again, ask for new permissions, or read documents from another Run or Project. It retains the same URL, acquisition time, hashes and original document identity, and reports the current numbered excerpt. If the cursor was not issued earlier in the same Run, the tool returns an explicit local unavailable result. If the original record is missing or changed after issuing a cursor, the verifier fails closed rather than silently substituting new bytes or retrying the request.

An excerpt number is an extraction unit, not an HTML section, browser position, or reviewed citation. A URL fragment does not select a later excerpt. The model does not need to read every excerpt; existing tool, context, and source acquisition bounds still apply. Multiple excerpts of the same source do not increase the original-source count in Deep research. Previously admitted Runs keep their original tool definition and receipt format. PDF-attached and selected-source turns keep their existing reader behavior.

Deterministic checks: `node --test test/local-gui-owner-web-excerpts.test.mjs` drives the normal GUI-to-chat gateway wire and native acquisition/storage using synthetic HTTP and model responses, with a fact available only in the second retained excerpt. It checks the original identity, Unicode and escaping bounds, cold readback, and no second acquisition. It also covers cursor authority, missing/changed data, cancellation, recovery around result commitment, and the legacy reader result. This is not a claim about model quality or an upstream service.
