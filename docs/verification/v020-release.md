## Control, correction and remaining limits

- Runtime centralizes bounded local-error/completion decisions; original Session owns durable settlement, cancellation and fencing. Permission, budget, identity, integrity and unknown effects retain their original owners and guards.
- Stateful report-reference correction uses an original Result basis anchored to the sealed proposal in a Session transaction. Child mixed-group refusal pairs the entire untouched group before dispatch and allows one bounded correction. It does not retry partial or unknown work, extend grants or create extra budgets.
- Deterministic Runtime/Session and process-interruption tests cover these correction paths. The latest natural real tasks had **zero correction hits**; do not describe the live batch as exercising the new correction branches.
- A committed Publication's ordinary asynchronous notification failure does not retract the committed receipt. The bounded notification window requires a responsive Node event loop; it cannot preempt synchronous blocking code or establish client delivery.
- New or explicitly updated project compaction configuration defaults to 60 seconds and allows at most 120 seconds. Existing explicit values and historical omitted defaults are preserved. Run/parent deadlines and cancellation may end observation sooner. A timeout does not cancel a remote request, release unknown occupancy or permit replay.
- Response plus Schedule remains unsupported. Historical protected-document profiles retain their restricted scope. No Python process isolation or browser UI qualification is claimed. Provider configuration, data transmission and currency costs remain the operator's responsibility.

Read the [capability and command limits](../research-project.md) before enabling a combination. The evidence supports the declared local project boundary, not every combination, production multi-tenancy, market-data correctness or investment recommendations.
