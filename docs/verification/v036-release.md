# v0.36.0 · Project Memory lifecycle

The existing [Project Memory](../research-project.md) owner now supports explicit
pin/unpin, pause/restore, and forget. Select specific active entry revisions or
opt out for one task without disabling ordinary report persistence. Restore
creates a new eligible revision instead of reactivating the old identity.
Default tasks keep the existing persistent behavior. Admission checks the
current eligibility of typed Memory after queueing and before dispatch; it
cannot retract a request already authorized past that check.

- **Frozen real qualification: 10/10**, above the 9/10 floor. All ten original
  cases used fictional term sheets, completed with one persisted report, and
  read back the original question, selected source and exact cited fact. There
  were no replacement tasks or retries.
- **Mechanism evidence.** Four positive selected cases had a native typed-use
  receipt matching the exact revision and a completed original Admission
  ticket. The default-mode positive instead matched the stored typed recall
  with actual provider-bound encoding and completed tickets at the original
  ordinals and input hashes. Before dispatch, the rubric was clarified to
  match the fixed contract: native selected receipts do not apply to default
  mode. The original task inputs, positive marker check, exclusions, and
  delivery floor were unchanged. All five positive markers matched and no
  prohibited synthetic Memory entered the requests or reports.
- **Safety evidence is separate.** Nine provider-free controls and one paired
  restore control passed. Typed-use evidence does not establish how the model
  reasoned. No claim is made about retrospective erasure from reports or
  arbitrary prose, real financial accuracy, or browser or production readiness.
- **Usage.** 37 HTTP 200 responses from OpenCode Go DeepSeek v4.1 Flash,
  $0 additional charge, no new unknown requests. Historical unknown usage
  was retained without replay or refund.
