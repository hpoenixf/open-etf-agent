## 原定范围的实现与验证

Knowledge 是主要增强模块；Session、Runtime 是原有预算与恢复职责的支持适配。
新任务固定来源、模型、页面向量及 token/查询限制；Session schema 7 在原工具派发事务中
同时预留工具次数、一次查询和两次本地协议操作。每阶段先记录派发，再执行；精确向量回执
在 Host 消费来源前落盘。跨 Run 的执行凭据、过期执行权、变化的模型/来源/向量、错误或缺失
回执及不兼容能力均被拒绝。

完整回执支持纯检索恢复，不启动 tokenizer/encoder；不完整或不确定操作保留额度并以
unknown 结束，不重新编码。原截止时间不刷新。五个真实独立进程 SIGKILL 边界均通过：
backend 前、tokenizer 派发后、encoder 派发后、回执提交但 Host 未消费、Host 已消费。
这组使用合成对话/encoder 和受控租约顺序，持久 Runtime 截止时间仍按真实时钟执行，
与真实模型证据分开。

真实本地 CPU 使用 MIT `intfloat/multilingual-e5-small`，revision 固定为
`614241f622f53c4eeff9890bdc4f31cfecc418b3`。业务查询在准入前没有预备向量，运行中只编码
查询并复用页面向量；token IDs 与独立 AutoModel 参考一致，最大向量差值为 **0**。
中断后新 Node 进程无须 embedding runtime 即可继续并读回原输出。编译后的 `dist` 与其
Python worker 也实跑同一路径通过。[源码 CPU 回执](../../engineering/v032-dynamic-20261118/real-cpu.safe.json) ·
[编译产物 CPU 回执](../../engineering/v032-dynamic-20261118/compiled-real-cpu.safe.json)。
这两项的对话 Gateway 为 fixture，不计入真实十次。
