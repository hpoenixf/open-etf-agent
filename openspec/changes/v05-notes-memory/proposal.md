# v0.5: derived working notes and explicit Memory are separate inputs

Baseline: v0.4 offline candidate 6e95fb0f6f75d41a695f2fc1e25491c104a8a1db, with live/semantic/license/publication still open. Authority: fixed public roadmap c390eb2dd951b53b1dab2d64a9cd72d216fde8dc. Existing original ResultRefs and exact reread remain the foundation.

A working-note compactor may summarize only complete older settled material while preserving original question/current group, exact source refs and immutable originals. It is derived context, not a new source, user instruction, permission or recovery checkpoint. Summary calls consume the existing root model allowance; the offline example is explicitly scripted and cannot prove live summary quality.

Memory is a separate explicitly selected local library with revisioned entries, operation receipts and one writer. Default tasks do not open a library or infer permission from words like remember/later. Save/revise/forget require trusted explicit intent outside model arguments. Forget affects current recall and future projected typed Memory/derived-note payloads; it does not erase historical reports or arbitrary original user text.

No new runtime dependency, service, database, scheduler, plugin, automatic learning, vector platform, cross-process execution recovery or live provider. Writer ownership is local to the chosen library; failure/stale locks are not silently stolen.
