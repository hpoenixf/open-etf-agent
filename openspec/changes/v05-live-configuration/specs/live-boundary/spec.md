# Observable configuration and request contracts

- A caller-supplied trusted grant must confirm provider, synthetic-data and cost scope and an explicitly approved cumulative operator ceiling within the generic implementation safety limit before the configuration loader opens any file. Model arguments and environment flags do not construct this grant.
- The operator selects the file path. Bounded regular-file reads reject static symlinks, unsafe directory ancestry and group/other-readable file permissions. Parse with the runtime's environment parser, never source/evaluate shell code or mutate process.env.
- Accept exactly three distinct single-line assignments: CHAT_BASE_URL, CHAT_API_KEY and CHAT_MODEL. Reject unknown/duplicate keys, missing/empty values, embedded line breaks and oversized input. Errors never quote values or file contents.
- Match the configured base URL and model against the reviewed exact scope. HTTPS, no userinfo/query/hash or redirects; append only the literal /chat/completions suffix when needed. Do not silently choose a different provider/model after a denial.
- Credentials are accessible only to the model client. Generic JSON serialization of the configuration omits the credential; this is defense in depth, not permission to print the property deliberately. Examples, tests, artifacts and build copies contain only original synthetic placeholders.
- No default command reads the real local file or makes a request. Live acceptance uses this project's explicitly approved cost/data boundary and finite request allowance. Client metadata must truthfully identify this project; never impersonate an approved third-party client or alter privacy/account controls to bypass refusal.
- Authorization failure, provider rejection, quota exhaustion or the local request cap stops the affected test without automatic retries/fallback/extra purchase. Store safe request-count, usage and receipt observations separately from live semantic review.

## Acceptance policy update (2026-10-27)
The project acceptance policy requires Runtime correctness rather than semantic model-answer quality. Keep output-quality observations separate; do not treat incorrect prose as a Runtime failure or a reason to tune prompts/retry. Assess source/parameter fidelity, lawful dispatch or rejection, resource bounds, partial effects and real saved artifacts. A missing original rejected input remains unverifiable, not automatically correct or buggy. Mechanisms absent from the live trace remain unverified.

## Public CLI portability extension (planned before tests, 2026-10-27)
The CLI requires explicit provider, synthetic-data and cost confirmations, a finite caller budget, expected endpoint/model, config, baseline, shared ledger and output paths; no historical grant is implicit. Accept only original local pins or independently read-back remote equivalents with the same fixed source/fixture blobs. Require the selected baseline to be its repository root with a clean tracked/untracked worktree before importing code. Reject wrong versions, wrong directories and dirty worktrees before network dispatch. Fake tests must not load the real local credential file. Preserve first-batch adapter hashes and original results unchanged.
