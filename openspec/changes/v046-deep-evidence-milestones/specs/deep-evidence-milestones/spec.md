## ADDED Requirements

### Requirement: Deep milestones describe observed Runtime effects

A newly admitted explicit Deep Run or Auto Run with the original first settled Deep selection SHALL derive milestones only from its immutable research profile and the original Runtime's paired Host evidence. Prose, discovery snippets, malformed pairs, provisional effects and unknown dispatch SHALL NOT count as read source entries. An original web document revision or local page entry SHALL be counted once. A known, settled source refusal MAY be counted as a check but not as an original read. Neither a terminal status alone nor a progress claim SHALL stand in for successful delivery readback.

#### Scenario: Paired evidence, known unavailability and cold delivery

- **WHEN** a Deep Run receives a valid original source, a repeated read, and a settled source refusal
- **THEN** its original evidence count deduplicates the repeated source; the refusal is represented separately; and the terminal delivery milestone is visible only after the original answer or report is independently readable
- **AND** the same evidence and delivery state are readable after reopening without a model or tool call

### Requirement: Existing authority owns research and synthesis

The Runtime MAY fit source-aware advisory text into its original reserved working input, including a prompt to synthesize on the last remaining Main round under the existing counters. This advice SHALL NOT generate another effect, make a budget grant, change tool availability, truncate an otherwise-admitted input, override cancellation, or block a valid final if evidence is absent. Explicit Standard and ordinary Auto SHALL keep their existing behavior, and earlier immutable Task/Runtime profile revisions SHALL not be reinterpreted.

#### Scenario: Last existing round after source check

- **WHEN** a new Deep Run reaches its last remaining Main round under original counters
- **THEN** only the existing next request may include a bounded synthesis reminder
- **AND** tool definitions and caps are unchanged; if the reminder does not fit, the original working input continues without it
