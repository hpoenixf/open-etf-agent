# Prospective Knowledge guidance repair

The original fixed v0.23 candidate completed ten real tasks with a frozen mechanical result of **8/10**, below the required 9/10. All 38 physical responses had complete Go zero-charge usage evidence. The original results are retained and are not combined with a future cohort.

One failed predicate compared a certification query case-sensitively even though Knowledge already performs case-independent lexical matching. The original successful empty result and subsequent model adoption were independently confirmed. A separate future evaluator may compare the same phrase without case sensitivity while still binding the result to the actual unmodified query hash. This does not change the original score.

The other failed task used a different query from the one requested. Its actual same-Run continuation and original evidence readback succeeded, but that does not excuse the query deviation. Independent review also found unsupported exclusivity, inconsistent uncertainty and commentary attributing an unstated premise to a question. Source citations and successful persistence do not prove those statements correct.

## Minimal product repair

- Knowledge tool guidance tells the model to preserve explicitly supplied query values, limits, order and grouping. It chooses query terms when the task leaves them unspecified.
- Knowledge task guidance distinguishes explicit statements and exclusions from information the sources do not state, scopes uncertainty, and requires consistency between the report and final answer. Derived Child commentary must be checked against the actual question and original evidence.
- No task-specific vocabulary, expected answer, query rewriting, ranking change, automatic semantic correction or extra model call is introduced. Original questions, selected data and the Child method remain unchanged.
- These instructions guide model behavior. They do not turn semantic accuracy or obedience into a Runtime-enforced guarantee.

## Binding and verification boundary

The additional question guidance is limited to Knowledge tasks. The ordinary non-Knowledge question wrapper is unchanged byte for byte. Both assembly and Child inspection derive the Knowledge question with the same switch.

The repaired candidate changes Knowledge task questions and Host tool-definition hashes. Previously admitted Knowledge tasks must use their original fixed executable source; binding mismatches remain fail-closed. No transparent cross-version migration is claimed.

The new provider-free tests inspect actual production Chat messages and tool definitions, preserve the original task question and query arguments, and exercise pause/continue and terminal zero-dispatch readback. Synthetic responses test prompt delivery and transport, not model compliance. A new fixed-source whole-ten cohort and independent semantic review remain required before qualification or release. The original 8/10 must not be relabeled or replaced with selected successful cases.
