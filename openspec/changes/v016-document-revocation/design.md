# Owner and compatibility contract

- Fresh explicit `document-revocation@1`, Session schema4, exact layout. Legacy v2/v3 cannot accept protected semantics. New attachment layout uses exact protected_outputs DDL including output@2 CHECK; even an old empty protected layout is rejected. No migration or schema autodetection.
- Original Source page identity and ResultRef remain unchanged. Ordered document page manifests bind name/version/page hash. Acquired Source dependencies only grow. Original Session records disclosed query facts separately, never as Source/ResultRef. Query executes original pure searchPages inside the short transaction after current grant filtering and before rank/limit; empty allowed set gives no candidates. No reusable permit or second budget claim.
- Exact original proposal/cursor/call and fence are checked in tool reservation. Model/tool admission checks the full durable Source and hint sets in the same transaction as budget consumption. Revocation is monotonic, available after completed Runs without an active lease. Admission wins first: its one already admitted operation may finish; revocation wins first: no new claim/disclosure.
- Report remains an original independent effect. Session registration associates original immutable report/revision, not another publication receipt or success event. It occurs after actual files and before paired checkpoint, against the persisted dispatched save call. Original final Publication (including idempotent return) requires exact persisted Host receipt, paired result and current dependencies. Saved registered reports from failed Runs remain readable only under current eligibility.
- Stable artifact root marker binds authority/library/root/run before any protected files. Protected record/revision schemas and identity forbid missing-marker legacy downgrade. Full current dependency set, not old saved deps hash alone, controls reads. Report, manifest, actual record bytes, UTF-8/NUL and original nine-field receipt are checked by existing owners. Exact source payload prevents unbound extra fields.
- Raw-row CSV uses the original encoder. At least one actual acquired Source is required inside matched reserve before tool increment; hints do not qualify. Ordered zero-to-sixteen protected attachments have exact descriptors/protection/requestHash/encoded bytes. Registered output metadata is bounded to64KiB, transient proof to22MiB; proof bytes never enter SQLite. Unregistered standalone CSV is not Reader-readable.
- Protected Host snapshot is exact and distinct from legacy Host@2. CSV result descriptors are admitted only in exact matched original committed/failed-terminal result slots, original paired messages, or a hash-validated working view matching that same paired call and entire result. No recursive marker exemption; actual stored bytes are unchanged. Cold recovery keeps original ResultStore and Artifact verification. Unknown/partial effects and actual kill windows never trigger effect replay.
- Reader opens original Session readOnly; every GET/HEAD/root checks marker and current qualification. Its report/CSV/metadata/revision/source paths retain original immutable identities. CLI requires explicit profile, exposes only control metadata outside gated content methods, and does not enable plugins/hooks/Child/Memory/compaction/PDF/worker execution. ReadOnly facade exposes the original three Publication reads, not writer methods.
