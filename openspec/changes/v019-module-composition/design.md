# Design decisions and retained failures

The implementation preserves original domain owners instead of introducing a generic plugin framework or merging incompatible persistent protocols. Host-owned catalogs, trusted extension descriptors and versioned bindings are explicit seams. Original grant, source identity, capacity, budget and effect guards are not optional configuration.

The first real C cohort exposed repeated managed summaries. A report already existed, but Main had not emitted its final answer. A subsequent summary hit a local role guard after original Admission dispatch. Unknown classification was deliberately retained: a plain thrown error is not trusted proof of remote settlement or permission to reclaim capacity.

The repair addresses the cause rather than raising the external role cap: an immutable note frontier is validated against the original prefix, covered call groups and current source/Memory dependencies; unchanged evidence reuses its projection. Summary attempts are bound to the Run definition and increment in the same transaction as the original root reservation. Reaching the cap selects an existing valid projection or the original bounded context fallback before another summary is reserved. Effects and the latest group stay original. No transport settlement framework was introduced.

The new gateway-history-compaction@2 definition intentionally rejects silent migration of the earlier experimental contract. Actual old-reader refusal and new read-only success were tested with unchanged stored bytes. Keep old source and recovery materials for old Runs.

The first B cohort also exposed an overstrict oracle: it expected one MCP call although the selected trusted Skill and granted inputs permitted two original documents. Its failure remains in the original denominator; only never-started tasks continued. No passing sample was selected to replace it.
