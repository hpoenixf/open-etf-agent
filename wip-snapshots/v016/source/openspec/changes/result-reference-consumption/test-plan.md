# Acceptance plan — original scope and later evidence

The initial plan below was unexecuted when published. Actual subsequent executions and input identities are now in [evidence](evidence.md); this plan itself is not a pass receipt.

All inputs are original synthetic data. No private payload, model billing, browser, external site or new service is required. Start with the smallest failing contract-derived selection/binding case, not the full suite. Test names and exact commands are frozen with the tests after scope review; this document is not a pass receipt.

1. **Success, source to delivery.** Acquire a small same-snapshot table, select the exact two operand rows including a tail row, invoke the existing calculator and reopen its record. The next actual `createChatGateway` serialization must contain the same ref/hash/operands/unit/currency/cutoff/coverage. Use a controlled injected transport; label it synthetic, not real model evidence. Generate report numeric material and CSV from that ref, exit, and read original bytes in a separate process. Compare actual numeric fields/metadata and immutable receipt identities, not narrative keywords.
2. **Tail row / coverage.** A required operand beyond the selected window is unavailable; it cannot be filled from a preview, summary or supplied literal. Selecting the real tail row restores the permitted comparison. An intentionally partial but completely materialized window reports its true scope, never full-source completeness. Source bytes remain unchanged and rereadable.
3. **Currency and cutoff.** Same generic unit with USD/EUR mismatch, same currency with different dataAsOf, and unknown metadata each prevent a successful same-snapshot bound number. Equal metadata permits the original calculation. The result sent to the next Gateway retains the exact reason; unrelated report text remains deliverable. This is not a currency conversion or Temporal module.
4. **Unknown denominator.** Unknown/null baseline stays unknown, zero stays invalid for this ratio, and no finite caller replacement can bypass the original row. A known nonzero baseline gives the existing arithmetic. Unknown comparison cannot be exported as a verified zero or a successful ratio.
5. **Identity and kinds.** Tampered content, foreign/unacquired ref, changed selection or substituted row/hash cannot produce a bound result. A derived result cannot be imported as original source evidence. Distinct source identities with equal values do not merge provenance. Reopen retains the same old operands, not a newer source version.
6. **Local failure / independent body.** An unavailable comparison or bad optional numeric/CSV reference does not clear independently lawful body, add repair turns or forge an Artifact. An already committed Publication and original valid artifact remain readable after a later failed attachment/terminal effect. Genuine cancellation/storage errors remain accurately represented.
7. **Preserved existing paths and installation.** Existing unbound calculator/T3, ordinary CSV, immutable Artifact/Reader, Context exact reread and Publication independent-commit cases remain valid. No arbitrary prose correctness assertion. Freeze the final behavior/package inputs; run the necessary whole regression set once, then independently install/build and run the new built CLI/readback path. No new dependency is expected.

The original result-consumption article motivates these contracts; its private Python/financial examples and historical qualifications are not public acceptance. Only actual observations will be added to the owning evidence after execution.
