## 8.1 Original-contract-derived synthetic cases

- Preparation is immutable body, not a receipt; existing byte/Unicode/identity bounds remain.
- Initial commit and explicit replacement keep one stable block and ordinal; revision audit differs from current delivery slot.
- Exact body plus protected Host/Run facts returns the original receipt without a new revision. Changed bindings alone require replacement.
- Unknown/stale replacement cannot append; two-change quota comes from stored revisions and survives reopen; exact no-op remains free.
- Real SQLite event-insert/update failures roll back the version. Missing event is unavailable, not silently reconstructed.
- Foreign root/Child, altered receipt or body, stale lease and elapsed deadline cannot authorize new writes.
- Earlier body remains readable after failed/cancelled terminal. Another real connection reads an active body without taking execution lease.

## 8.2 Same Runtime and actual process boundary

- Same Runtime publishes sealed final text, then ordinary terminal bookkeeping; missing/version-mismatched binding fails before Gateway.
- Report-required failure and post-commit local failure/cancellation keep the original body but do not fabricate report/terminal success.
- Terminal resume validates receipt identity, not a checkpoint's claimed success.
- Kill an actual child after commit before terminal, verify retained active body, then use a different process/PID to recover the exact sealed final and original receipt with no new model call.
- Existing session CLI starts `durable-publication`, reads selected revision/current event, and resumes in distinct invocations. Actual report Artifact bytes remain separately readable.
- Invalid/read-only options and absent DB never create a new session as an accidental read side effect.
