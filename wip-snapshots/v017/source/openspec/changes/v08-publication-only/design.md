# Publication-only design — original-owner adaptation

## Original facts, one bounded slice
Publication separates prepared content, committed body, current delivery position and Run terminal status. The original ETF Agent owner and its failure cases motivate this adaptation; no private implementation/SQL/prose is copied. Synthetic Markdown is the first public slice, not the complete original multi-block/citation/preview system.

The same root Run owns one stable Host block ID (`answer`) and delivery ordinal 1. Neither changes with revision or body hash. A canonical receipt binds Run/root, block, revision, ordinal, exact payload hash and protected-binding hash. Root is the existing public grant namespace, not an account or login. All mutations use the existing Session claim/fence/lease/deadline; a Child cannot publish the root answer.

`preparePublication` validates immutable plain Markdown within the existing 64,000-byte bound, without creating a receipt, resolving private sources, verifying semantics or claiming Artifact save success. No caller-supplied receipt or revision is accepted as authority. Its content hash covers exact text: no trim/equality normalization. A store-produced binding hash covers the original definition and current persisted Host facts; callers cannot assert that changed protected facts are unchanged. This retains actual local provenance without introducing private source resolution or trusting model-declared authority.

## Storage belongs to the existing Session
Schema 2 adds only `publication_versions` (immutable revision audit) and `publication_events` (one current delivery slot per root). The latest version is the head; there is no parallel head manager or general event bus. Both new tables belong to Publication, inside existing short synchronous SQLite transactions. No model/file callback executes while the database transaction is held.

`claim.publish(prepared)` inserts revision 1 or returns the original receipt for the exact unchanged current body/bindings. Changed content/bindings at the same block needs explicit `claim.replacePublication(prepared, expectedRevision)`; replacement never turns into append. CAS is checked before no-op. A real replacement appends a version but retains ordinal 1 and updates exactly the existing event. Missing/corrupt delivery identity causes rollback, not reconstructed success. Two changed replacements per block are allowed, derived from persisted revision minus one; no new policy configuration or counter. A no-op consumes no revision or slot. The one-block slice cannot reach the original eight-per-Research total ceiling.

Selected read APIs: `store.publication(runId, revision?)`, `store.publicationRevisions(runId)` (at most three), `store.publicationEvent(runId)` (current slot), and `store.confirmPublication(receipt)` (exact original revision read). Every read checks stored Run/root/bindings, body hash and current head/event consistency. Historical version audit does not pretend its old event is still the current delivery projection. Missing/foreign/altered identities remain unavailable. Reading does not claim or resume execution, call a model, fabricate terminal success or authorize another Run. Failed/cancelled/expired Runs retain committed readback; new mutations remain fenced.

## Same Runtime, no second executor
An explicit code-owned `publication@1` adapter binding activates this module; omission/mismatch on resume fails before model dispatch. The same Runtime prepares/publishes its sealed final text before the ordinary report-required and terminal path. The last sealed checkpoint makes a crash after commit recoverable by exact no-op and original receipt confirmation; no extra model request is needed. Normal report/log/terminal failure cannot erase publication. An optional `durable.onPublication` observation seam can test the exact post-commit/pre-terminal crash boundary; it does not own commit identity or a queue.

Terminal resume confirms any recorded Publication receipt against the durable owner. An old terminal result cannot assert a changed/missing receipt as committed. Version-bound configuration prevents the older entry from silently discarding the feature. Files/Artifact and SQLite remain separate owners and are not one atomic transaction. Existing report output and its old immutable Artifact readback stay independently available.

## CLI and exclusions
A local CLI demonstrates initial commit, explicit replacement and chosen revision read; a same-Runtime synthetic demo uses the existing fixture/report assembly. No HTTP service, credentials, background worker or browser. No old-active-schema migration; an old database is refused before writable recovery. The v0.7 Artifact format remains readable separately.

## Qualification
Loadable tests derive from original duplicate/conflict, stale CAS, missing-event rollback, committed-body-survives-failure and fresh read-without-lease counterexamples. Prove protected binding changes defeat a text-only no-op; stale/foreign/cancel/deadline denies new effect while prior body survives. Add same Runtime missing-binding refusal and actual child-process crash between publication commit and terminal. Independent install/build/CLI readback and old Artifact regression follow. Historical expanded298 is not a denominator for this smaller module. Runtime correctness only; semantic status remains unreviewed.
