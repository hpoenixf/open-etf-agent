# Session hot-journal admission — approved narrow implementation decision

Root decision 2026-10-28: prepare a local candidate; no remote publication or v0.11 qualification is implied. This new maintenance change does not edit prior archived evidence. The original automatic artifact-kill test remains unchanged.

## Original assumptions and behavior retained

The existing openSession admits operator-selected safe directories by readonly exact schema/version/application ID, closes that reader, opens writable and revalidates. That gap already relies on no concurrent incompatible schema/path replacement; it is not an atomic defense against same-user adversarial filesystem mutation. Existing Session supports legitimate multiple connections and competing Workers sharing its lease/fence. Single user does not mean single opener.

Retain that normal path and all existing tests. No new marker/creation receipt, PID proof, launcher, lock manager or CLI. Old compatible DBs without receipts remain supported. Restored inode identities are freshly checked on open, not compared with a new persistent origin identity. Unknown/future schema remains refused; no migration or automatic schema upgrade.

## Only extended error 776

Add src/session-recovery.mjs and one call-site adaptation in src/session.mjs. Only precise SQLITE_READONLY_ROLLBACK enters bounded copy admission. Trusted root contract explicitly forbids concurrent external schema modifications, pathname replacement or uncoordinated restore; compatible module DML/openers remain supported. No claim of global quiescence or eliminated TOCTOU.

1. Gate only this path on the audited native SQLite version 3.53.4; unreviewed versions explicitly refuse recovery scope while normal opens remain unchanged. Check existing ordinary singly linked DB/journal and absent WAL/SHM. DB <=64 MiB, journal <=64 MiB, combined <=96 MiB; input is streamed in <=64 KiB chunks. The two initial captures total at most 192 MiB; candidate rollback target is also limited to 64 MiB. These limits apply only to 776 admission, not normal opens. Overflow is an explicit scope refusal, not corruption. Poll a 5-second elapsed admission bound between synchronous operations; do not claim interruption of blocked filesystem/native calls.
2. Read only bounded journal header/footer metadata for scope checks. Reject terminal journal magic conservatively: SQLite 3.53.4 reads external super-journal paths only through that footer. A coincidental matching tail is an intentional false rejection; no path parsing or fallback. Reject unsupported/invalid first page/sector-size header metadata and rollback target over 64 MiB; these are resource guards, not schema admission or journal repair.
3. Create a unique owner-only sibling capture directory outside the target Session directory; copy DB/journal to a pristine pair and separate candidate pair. A writable safe parent is required only for this recovery path. Original unknown-schema directory is not mutated. Native SQLite recovers only the candidate, then runs the existing exact schema validator.
4. Compare current original file identity/content and sidecar set with the capture immediately before original writable open. Drift fails explicitly, without retrying/overwriting. This detects observations; it is not a lock. A competing legitimate opener may recover first and cause a safe drift/busy refusal; caller can perform a later ordinary open. No schema/Run ownership is stolen.
5. Let SQLite recover the original under its native locks, using a 1000 ms connection busy timeout before the first schema query (the ordinary path's later timeout remains unchanged), then run original schema validation and ordinary Session setup. No manual journal deletion or DB replacement. After original native recovery starts, failures may have partial effects; retain pristine capture and expose a bounded failure with its recovery location, never auto-restore or retry. Pre-admission failures leave original bytes unchanged. Clean only this invocation's copies on pre-admission refusal or completed success.

## Root-approved normal admission timeout placement correction (07:01 UTC)

The first complete candidate run was 370/371, with the original competing-Worker case reporting native BUSY 5; its complete stack was not retained, so its exact callsite remains unproven. A separately authorized once-each fresh synthetic diagnostic then demonstrated that both unchanged baseline and candidate immediately fail in the initial readonly `PRAGMA user_version` under a real 150 ms EXCLUSIVE lock, with original DB bytes unchanged and successful later opens. This proves a shared admission-wait gap, not the unique cause of the full-run failure.

Root approved moving the existing 1000 ms native busy policy to both initial connection constructors, including the readonly validator. This is a bounded timing change to the normal path, explicitly superseding the earlier promise of unchanged timeout placement; schema validation order, readonly mode, error 776 routing, claim/fence, effects and business retries do not change. No application retry loop is added. Tests must demonstrate actual 150 ms release success and a lock held beyond 1000 ms still producing native BUSY, original bytes/facts intact, followed by ordinary opening after release. Existing Worker/crash tests remain unmodified. Independent re-review and a new authorized full run are required; neither prior partial green nor diagnostic closes the original gate.
