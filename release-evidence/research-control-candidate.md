# Research control candidate

One release owner: the native research runtime. The first integration surface is
the owner financial chart workflow. Stable v1.0.5 is the integration base.
Reserve the next version number only after checking the release and WIP refs
through the existing single writer.

- Standard remains explicit; Auto may switch to Deep at admission for a
  multi-step filing analysis, or once mid-run from verified original evidence.
  The switch keeps the same Run, source receipts and physical request limits.
- A host-owned registration controls acquisition accounting. A proposal
  group with at least one dispatched acquisition consumes one evidence round.
  Separate counters report physical requests and elapsed time. Output and
  bounded approved local helpers do not debit evidence rounds or tool calls.
  Unregistered or rewritten tools retain the default debit.
- At 20/50/80 percent of the acquired evidence allowance, send at most the
  newest advisory along with the next normal request. No timer, no additional
  request or quota, no evidence-completeness claim. Never duplicate after a
  settled checkpoint; if an optional advisory did not fit, defer it naturally.
- On tool allowance exhaustion, remove acquisition tools while retaining
  bounded local synthesis and chart tools. Keep a last protected request for
  publishing, with the original Publication owner and exact citations.
- Release checks: explicit Standard never promotes; Auto preserves receipts
  and counters; mixed rounds only debit acquisition; jumping across milestones
  sends only the highest; chart and body publish after acquisition exhaustion;
  open/restart retrieves the same body, original cites and exactly the charts
  persisted for the completed Run. No real request shall be replayed merely
  because a local workspace was lost. Use a new, fixed stage cohort.
- Independently verify Stage browser behavior, stable deployment identity and
  real runtime qualification before a public release. Research/Publication
  behavior is one coherent release. PG, scheduling, provider routing and
  history management are not part of this version.
